# 真实模型日常场景观察

[返回 Wiki](README.md) · [后台任务](后台任务.md) · [模型调用](模型调用.md)

本页记录 2026-11-12 一轮有限的日常场景观察，用于解释当前能力与后续设计依据。使用测试实例已配置的真实文本模型、两个独立 Agent 身份和新建虚构空间，没有把既有个人记忆发送给模型。原始执行器、请求与产物只在本地忽略目录保留，不进入仓库。

## 场景与观察

资料包含 14 条虚构记忆，涉及两个项目的数据库、日志、发布安排和全局偏好；另有 1 条虚构 Secret 和 4 条带真实采集 ID 的测试消息。通过真实 MCP 和 Web HTTP 调用，后台模型沿现有持久任务与额度入口执行。

| 场景 | 当次观察 | 可以支持的结论 |
| --- | --- | --- |
| 默认范围整理，连续两次 | 两次失败，仅旧版 model_response 代码，未写入产物 | 旧错误信息不足，不能准确判定具体失败原因 |
| 指定 8 条较早资料整理 | 生成 4 个主题，保留项目条件并报告发布时间冲突 | 本次能按范围组织主题，未自行裁决相互矛盾的用户确认 |
| 更正普通记忆并带原主题再整理 | 原主题追加修订，依据指向新版本 | 本次可沿真实依据维护已有主题 |
| 从选定消息提炼 | 新增 2 条记忆，保留用户确认，未把助手猜测升级为事实 | 本次来源与条件整理符合预期 |
| 重复提炼同一消息 | 成功，新增 0 条 | 本次模型能利用对照记忆避免重复；不构成跨任务去重保证 |
| 重放首次整理的同一组 ID | 成功生成 3 个入口 | 早期失败未稳定复现，不能宣称已确认根因或已被某次修复消除 |
| 带已有主题复查相同数据库／日志资料 | 成功，新增 0 条 | 此次对照完整时能够选择不改写已有主题 |
| 补入报表导出验收方法并带已有主题 | 更新同一主题为修订 2，使用短标题，正文与 3 条依据分别展示 | 此次可扩充入口覆盖，同时保留细节在普通记忆中 |

共执行 9 个文本任务，每个执行一次，7 个完成、2 个早期失败。主题产物带真实输入关系，更正后的普通记忆可由另一 Agent 读到，召回可由原召回身份反馈。Secret 对象未进入整理输入。

本轮跨 Agent 召回实际走关键词降级，因此只证明该次跨身份的读写／反馈链路，不构成语义检索效果结论。真实资料集未执行遗忘；更正、遗忘和后续读取的确定性生命周期另以独立测试库回归。

这不是模型排名、稳定成功率或完整质量评测。硬校验保证来源和修订等结构约束，模型仍可能遗漏、重述或归纳不当；需结合真实使用继续观察。

## 由观察推动的修正

- 任务保存服务定义的安全错误说明，页面不再把所有失败都归因为“检查模型配置”。不记录模型原始响应或凭据。
- 成功但没有产物明确显示“本次无需更新”；最新任务无产物时不再跳到更早任务的旧结果。
- 有新产物完成时刷新看板记忆，避免只有主题入口更新而正文卡片仍显示旧数据。
- 消息提炼的 note 类型约定增加后端强制校验，不能靠合法 topic 枚举绕过。
- 明确主题正文首行只写短标题，随后换行说明；避免整段说明成为导航标题。已有主题不做无依据的批量改写。

这些修正分别用产品回归与浏览器检查验证，不能把它们当作前两次随机输出失败的已证实根因。浏览器另外以仅限虚构空间的临时 HTTP 响应模拟，验证采集消息页显示安全任务错误、后续成功清除旧错误并显示“无需更新”；验收后已恢复真实响应，未改写后台任务记录。

## 自动整理前的设计结论

现有按钮每次重选最新最多 10 条，没有历史处理进度；新主题还会进入候选，较早记忆可能一直碰不到。同一资料范围不带相关已有主题时，模型也可能创建相近入口，提示词中的“不重复”无法弥补缺失上下文。

后续自动化应分开选取“待处理的普通记忆”和“用于对照的主题”：按记忆 ID＋修订保存处理进度，首次分批覆盖历史，之后处理新增／更正资料；成功但无需产物也推进进度。主题按范围或已有依据关系补读，不挤占普通记忆批次；不因标题相似就自动合并或删除。

在上述初期观察阶段，自动调度仍缺独立启用状态、每轮工作量／每日调用预算、失败退避和可理解的进度。后续已经实现按普通记忆修订自动推进，见下一节与 [后台任务](后台任务.md)；采集消息提炼保持独立边界，不能把启用主题整理解释为自动发送全部原始对话。

## Provider 与自动整理的后续有界复测

同日新增 Provider 共用连接与持久自动进度后，在独立实例复用测试模型连接；每轮新建相同内容的 5 条虚构普通记忆，每批 2 条、上限 3 次尝试。没有复制个人记忆／Secret，也没有对既有真实空间启用自动发送。

| 阶段 | 实际观察 |
| --- | --- |
| 初始自动批次 | 3 次尝试：1 批完成、2 批引用校验失败，完成 1／5 条 |
| 模型输入去掉内部调度恢复元数据 | 3 次尝试：2 批完成，最后一批因输出未完整结束失败，完成 4／5 条 |
| 文本输出预算设为 8192 | 3 次尝试：2 批完成、1 批确认把记忆 ID 填入事件来源，完成 3／5 条 |
| 保持 8192，明确区分事件来源与记忆关系、移除主题示例的事件来源字段 | 3 批均完成，5／5 条推进，生成 3 个简短主题入口 |

本次共 12 次自动文本处理尝试，没有把中间失败隐藏为稳定成功率。模型有随机性，不能据此单独归因每个提示词变化；最终结果只证明该组虚构资料跑通。后端引用／修订校验始终保留，没有把错误来源自动改成正确关系。推理模型的输出预算可包含思考消耗，应按模型能力设置，不把8192当作所有模型通用推荐。

随后用本机模拟 Provider 验证页面配置交互，和上述真实模型结果分开：两个用途共用同一连接；各保留未提交并发草稿时轮换虚构 Key，草稿与修订能同步并成功保存；用途在另一管理操作中改变时显示冲突，明确重新载入后恢复新值。另有等待模型额度期间暂停的确定性回归，确认取消者不再发送HTTP。模拟 Key 与资料都是虚构；没有把这部分请求当作真实模型质量证据。

## 客户端安装与真实 Skill 接续验收

2026-11-12 针对分发产物与实际 Agent 使用另做验证。使用独立数据库、根私钥、空间与两个接入；没有把个人记忆或生产凭据作为夹具。执行器、认证临时副本和原始记录不进入仓库，结果通过真实读回及只读数据库查询核对，没有仅以模型最终回答或进程退出成功判定完成。

安装观察：本机 macOS ARM64 从实际 HTTP 下载并校验 release 客户端，分别执行旧版升级、新装和重复 init。原 Agent、接入凭据、其他 MCP 与注释保留；Codex 实际插件缓存中的 4 个日常 Skill 文件与源码一致。Bash 与 Nushell 安装均执行过。Linux ARM64／x86_64 客户端另在 bookworm 构建并实际执行，导出的 4 个 Skill 文件逐字节一致。macOS x86_64 目标交叉构建后在 Rosetta 下执行并核对导出，四个平台的下载产物均已生成；本轮未在物理 Intel Mac 上测试，也没有创建或发布正式发行。

真实客户端为本机 Codex CLI 0.165.0-alpha.1.2。首轮执行器使用禁止审批的非交互设置，MCP 写入被拒绝、本机 CLI 网络受沙箱限制，任务未完成；不能把这轮进程正常退出解释为业务成功。改用标准自动审批模式后完成两个独立会话，没有使用跳过审批或跳过 hook 信任的参数。运行权限仍由宿主决定，参见 [Codex 自动审批](https://learn.chatgpt.com/docs/sandboxing/auto-review)。

| 场景 | 实际观察 |
| --- | --- |
| 无手工指定 Skill 路径的保存任务 | 两个会话均主动读取已安装的日常 Skill 与相应参考文件，按实时能力和权限使用 MCP |
| 首个接入保存经验 | 保存两条项目经验、一个独立临时便签和一个主题入口；读取回执后核对内容与关系 |
| 第二个接入接续与更正 | 通过记忆重建巡检步骤，保留条件和授权边界；原发布记录更正为修订 2，主题也更新为修订 2，未新增冲突安排 |
| 主题、反馈与遗忘 | 当前项目有一个主题和 3 条当前关联；5 个条目写入评价；仅临时便签被遗忘，项目经验保留 |
| Secret 文件保存与托管取用 | CLI 直接读取私有虚构文件，数据库只有一条 Secret；另一接入按公开契约和修订托管执行本机 JSON 结构校验，退出成功且临时文件已清理，审计回报成功 |
| 原文边界 | 两个成功会话的事件记录均未出现准备的虚构用户名／密码值，模型只处理公开说明、契约和引用 |

这说明上述有限日常链路跑通，不是 Skill 稳定遵从率、所有 Codex 版本或语义检索效果的保证；当次服务未配置 embedding，召回实际走关键词。doctor 的测试上传不能替代原生 hook 触发验收，新安装仍须用户审核信任并在真实消息后检查来源。本轮没有修改信任记录，也没有更新生产。

## 2026-11-13 对话增量提炼与标题

使用隔离 MySQL、虚构的“青铜航线数据库检查→补充记录要求→杭州徒步偏好”三轮资料，调用本地已配置的文本模型；只复制模型连接密文，不读取或发送真实空间原始对话。首轮发现整理示例的 topic 格式对 extract 存在干扰，模型两次返回无效结构、一次返回错误类型，均被校验拒绝且无部分记忆落库。

明确区分 organize / extract 的完整 JSON 示例后重测，三批均 done：标题前两批保持“青铜航线数据库复制检查约定”，第三批改为“周末杭州轻量徒步偏好”；得到三条带实际事件来源的普通记忆，消费完成数从1递增到3。第二条保留了旧条件并加入新的记录要求，仍存在事实粒度部分重叠的可能；有限对照不等于全局语义去重。

持久回归补充：零产物也推进、快照之后新增消息留到下一批、迟到旧事项不回拨较新标题、固定标题、不同 Agent 同 session_id 隔离、整理与提炼交替、暂停释放、限流重试、在途遗忘阻断、共享预算，以及超大 JSON 转义事件冷却后不阻塞其他工作。评测工具与原始响应在 ignored `.local/`，不进入仓库。此三轮是行为观察，不是普遍模型质量保证。

## 2026-11-16 真实对话历史质量评测

用户明确授权后，只读抽取生产技术/产品/运维等对话，在隔离库回放当前开发版的自动提炼；不写回生产，不读取 Secret 原文。预先冻结评价维度与关键事实，再复核候选。评测工具、真实样本、原始响应与逐条报告均留在 ignored `.local/`，不进入公开仓库。

本轮覆盖11个分层选取的会话、365条待提炼消息，另8条此前消息仅作上下文；既有20条普通记忆作对照。不是随机抽样，不代表所有用户场景。默认模型 `deepseek-v4.1-flash`、最大输出4096：41批中20批成功、21批因输出未完整结束被拒，成功消费163条，202条仍未消费，生成45条候选；问候和一次性生成标题两组负例均无候选。模型已知用量401,031 Token，无未知用量请求。

透明记录捕获到的19次默认失败均为 `finish_reason=length`，4096个completion token全部用于reasoning；另两次失败发生在接入响应元数据记录前，仅有后端错误和用量记录。失败同样消耗Token。将三批失败样本在另一隔离库重建消息、当时记忆及标题，额度改为8192，三批均通过实际Worker并写入共6条候选；一次输出实际需要4749个completion token。对照样本少且模型有随机性，不能据此承诺8192适用于所有模型或能恢复全部失败。

人工按统一口径复核45条：21条可直接复用，19条需要压缩/合并/收口，3条有旧方案或未完成状态遗留风险，2条有语义误读或未经说明的范围限定。这是本轮人工分级，不是统计意义的准确率。主要风险包括：把用户对文案的批评反向理解为长期偏好；方案已被否决而旧部署要求仍存；同一事项“尚未完成”与“已完成”作为两条无替代关系的记忆并存。

因此，虚构三轮验证通过只能证明基本行为，不足以证明真实历史可全量无人值守发布。下一轮应重点验证模型预算与length恢复、减少任务流水、对否定/反问保守提取，以及读取相关旧记忆后的修订候选和失效处理。已有数据的完整保全和“不凭模型猜测覆盖普通记忆”约定继续适用。


## 2026-11-16 两阶段提炼验收

固定365条待处理消息与6个未参与主调优会话的115条可处理消息，另8条旧上下文，共同验证候选生成、相关普通记忆检索、核对、事务发布与修订确认。实例隔离，不修改生产。主回放固定规则A；据发现的问题形成最终规则B，再做同输入核对、失败恢复和虚构端到端演示，不混称为最终提示词全量一次通过。

480条待处理消息最终均完成；系统动作合计新增117、提出修订2、跳过43、暂缓9。数量不是正确率。主回放有3个终止批次（空标题、单候选引文超量、响应不完整）和1次临时故障重试；22条失败消息由最终Worker经5次阶段调用恢复，返回均完整结束。无主要事项可保留原名；超量候选仅保留有界展示并强制暂缓，不能按截断证据发布。源码/模型仍可能拒绝其他不完整或无效响应，原消息保留。

两组文本请求110次，已知1,176,624 Token，另1次用量未知；另有2次定点核对试验，不含本地探针/demo和其他后台用量。此次离线实例未复制embedding配置或建立向量索引，相关检索主要依靠关键词/词面补充，不代表语义检索准确率评测。

观察到旧决定变更能提出有来源、确切修订的草案，旧上下文单独产出被暂缓；定点修复让“修复完成”与旧“尚未修复”转为修订并保留部署状态的不确定性。仍有一般知识偏多、任务事实偏细或适用范围偏宽的情况；不保证全空间去重与全部过期事实都被识别，不提供未经人工标注的“准确率”。修订仍待用户确认。

12项独立MySQL回归、38项前端库测试、3项请求生命周期测试通过，Wasm/正式bin-lib检查与独立审阅通过。具体来源、候选、提示词快照和逐项私有验收记录仅在忽略目录.local，不进入仓库。
