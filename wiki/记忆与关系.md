# 记忆与关系

[返回 Wiki](README.md) · [表结构](数据模型.md#memory_links) · [后台任务](后台任务.md)

结构化关系和正文分开保存，具体怎样拆分知识仍交给 Agent。不会强制每条记忆填写机器、标题或固定模板。

## 普通记忆与主题

`memory_type=note` 是默认普通记忆，`topic` 用于简短主题入口。主题仍是可修订、可召回、可遗忘的记忆，没有另建 Wiki 页面表或目录树。显示名称取正文第一个非空行，去掉开头的 `#` 并最多保留 80 个字符。

主题正文介绍适用场景和去向，细节保留在关联记忆中。主题与普通记忆同样登记关键词和可选向量索引；索引成功与内容正确是不同状态。

## 两类关系

| 类型 | 目标修订 | 语义 |
| --- | --- | --- |
| `reference` | 必须省略 | 进一步阅读入口，跟随目标当前内容 |
| `derived_from` | 必须是实际读取的正数修订 | 本条结论由目标内容整理而来，保留依据版本 |

例如，主题 T 根据操作手册 A 的修订 3 整理：T 指向 `A@3` 的派生关系。A 更新为修订 4 后，T 的依据仍是 3，不自动升级成已经核实过 4。

新增关系必须指向同空间真实、未遗忘的记忆；新增或改变派生依据时，目标修订必须等于当前修订；原有关系可显式保留，后台合并也只能保留已读主题原来的依据，过期仍标记 needs_review。Secret 可作为普通导航引用的目标，不能作为派生依据；Secret 自身也不能改成主题或附加出边。

每个源修订最多 32 条关系，不允许自引用或相同目标＋类型重复。普通引用允许互链，派生关系做有界遍历并拒绝循环；检查超过 512 个依据节点时拒绝本次写入，提示缩小范围。

## 修订与事务

`remember` 同事务保存正文、来源、关系、幂等回执和索引任务。`correct_memory` 要求 `expected_revision` 匹配当前头部，追加新修订，不就地覆盖旧正文。

更正时省略 `links` 保留原有关系，显式 `[]` 清空；省略 `memory_type` 保留类型。保留旧关系允许继续保留过时依据，以便阅读时提示；重新核对后显式更新派生修订，不能把“省略”解释为已核对新版。

普通更正沿用空间写锁，后台生成也复用事务内写方法。并发修订发生冲突时重新读取，不能静默覆盖。

## 读取、反向引用与过期提示

| 接口 | 返回内容 |
| --- | --- |
| `get_navigation` | 当前有效的主题入口 |
| `get_memory` | 正文及 `knowledge.outgoing_count`、`knowledge.needs_review` |
| `get_memory_links` | 当前引用；`incoming=true` 读取反向引用 |

入口和关系每页最多 20 个对象，另受 `max_chars` 限制。预算按序列化 JSON 的字符计算，不是 Token；默认 3000，允许 1024～8000。游标按记忆 UUID 推进，预算不足时保留下一页入口。已知项目筛选包含该项目与空间通用条目。

反向引用只连接源记忆的当前修订，历史关系继续保存在数据库，但不冒充当前关系。目标或来源已经遗忘的内容不再供阅读。关联条目标记 `match_source=linked`，与 recall 直接命中区分。

`needs_review` 在读取时沿派生链计算，直接或间接依据修订变化都会提示；超过 512 个检查节点时也保守标记需核对。它不判断新旧事实谁正确，也不自动发起 LLM 重写。

当前 recall 不自动遍历关系、不做图排名。Agent 可先查主题／关键词，再按需沿边阅读；Web 提供同样的关联入口。

## 遗忘传播

遗忘依据时，派生正文也可能保留其信息，因此沿包含历史修订的派生关系递归清理依赖记忆。普通 `reference` 不扩大遗忘范围，旧导航边不会让已遗忘正文重新可读。

同时清理本空间 `knowledge_jobs` 的输入、结果和租约，取消任务，避免后台副本或在途响应重新发布被遗忘内容。当前以整个空间的任务副本为清理单位，没有精细到单个任务依赖。

这条规则较保守：即使某条当前关系已移除，只要历史派生修订可能保留依据内容，仍可能被纳入遗忘。不能把它当作普通导航的“删除一个链接”。

## 合并主题入口

`topic_alias` 表示合并后的旧主题，当前修订只保留一条 reference 指向有效主题（可有有限别名链，但禁止循环、跨范围或指向普通记忆/Secret）。原正文及原关系保留在历史修订中。直接读取返回 redirect_to，Web 继续打开有效主题；导航、看板和召回不重复展示别名。目标遗忘时清理别名，普通引用仍不扩大遗忘范围。迁移包保留别名类型与普通引用，并在关系落库后检查完整链路。

## 使用观察与事实修订

`feedback_recall.usage` 可独立报告真正使用过的返回项，结果为 succeeded / content_outdated / environment_blocked / unverified；reason 可选，非空时最多512 UTF-8字节、单行公开描述。evaluated/useful 只表示任务相关判断，不是使用或执行成功。未读取/未使用的条目不能全选；服务按原 Agent、召回ID、条目修订校验，最多20次召回、每次10项。未验证可晋级；最终结果不可覆盖，同一任务重试幂等，新尝试用新召回。

例如“这份流程对问题有帮助”可以只给 useful；“按流程执行检查通过”才给 succeeded；“流程有效但本机缺权限”给 environment_blocked；“已采用但结果还待确认”给 unverified。只记录 Agent 观察，不宣称独立验证。问题报告可唤起[独立维护](后台任务.md#独立低频维护maintain)，普通正文经真实报告、时序与当前修订校验后由 AI 自动维护；报告保留归属，不把一次环境失败写成永久事实。

默认推荐 CLI 安装的 Chromie Skill + MCP。Skill 在任务结束、最终答复前驱动反馈，MCP 负责身份、召回项和修订校验并落库。反馈是使用记录，不修改正文；只读业务检查或暂不更正记忆时仍可记录，用户明确禁止记录或反馈时不提交。当前是提示词引导，不能保证每次都反馈；没有反馈保持未知，不自动视为无用。
