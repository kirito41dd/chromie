# Web 控制台的阅读与异步状态

[返回 Wiki](README.md) · [后台任务](后台任务.md) · [Agent 与提示词](Agent与提示词.md)

界面使用 Slint／Rust 编译为 Wasm，通过少量浏览器桥接调用同源 HTTP。Slint 主要绘制在 canvas 上，正文选择、复制和焦点行为需要项目自己的桥接配合，不能直接依赖 HTML 文本节点。

## 页面入口

| 页面 | 与本轮能力的关系 |
| --- | --- |
| 看板 | 主题导航、自动整理进度和最近结果、记忆卡片阅读入口 |
| 采集消息 | 按 Agent／会话浏览原始事件，选择会话后可提炼当前页前 10 条 |
| 系统设置 | 管理 Provider，分别选择文本／embedding 用途和自动整理设置 |
| 召回调试 | 展示现有搜索过程；结构化关系不会自动扩展为搜索结果 |
| 炼化／夺舍 | 迁移类型与关系，导入前预览冲突 |

看板展示自动整理的进度、最近任务与结果，不再要求逐批点击。消息提炼独立发起，产生的普通记忆后续可进入自动整理。消息页未选择会话／无消息或正在加载时禁用提炼，并解释需要先选择会话；提交前说明消息将发送给所配置模型。

## 主题与关联阅读

主题导航先读取简短入口，打开后使用阅读浮层读取正文和关系。正文按服务端预算分段取回，引用与反向引用分别分页，保留返回栈；不会为一次点击自动加载整张关系图。

阅读浮层从顶部按自然内容高度排版，可滚动查看长正文，标题变化时重置滚动。引用入口支持鼠标与键盘；Esc 和关闭按钮退出，返回操作保留之前阅读路径。焦点哨兵必须保持零尺寸且不接收鼠标焦点，避免挡住浮层内的点击。

正文使用只读 SelectableText；内部处理原生选区，CopyBridge 把当前选区交给浏览器 copy 事件。无选区时使用展示层避免绘制插入光标，内容区域默认箭头指针，代码区域可使用文本指针。它是可复制的展示内容，不具备编辑和自动保存语义。

阅读器只请求公开正文与元数据，不获取 Secret 原文。Secret 查看继续使用独立验密、短时浮层与清理机制，见 [Secret 使用手册](../docs/Secret记忆.md)。

## 请求生命周期

Rust 控制器维护请求代际 Gate，浏览器桥接使用 AbortController。响应必须匹配当前代际和操作才接收，切换空间、退出或清理页面状态时使旧响应失效，不能把之前空间的内容渲染回来。

主题导航与阅读使用独立通道；文本模型配置与任务状态也分通道。普通消息读取只取消消息通道自身，不取消整理任务请求。跨通道只 abort 而不释放 Rust 加载状态，会造成永久“加载中”，因此页面统一清理与普通请求替换必须分开处理。

任务状态每 5 秒轮询，接口最多返回最近 20 项，卡片展示最近 3 项摘要及有限冲突说明。成功但零产物显示“本次无需更新”，阅读结果入口只对应最新任务，不在其没有产物时跳到较早任务的旧结果。有新产物完成时同步刷新看板记忆；失败显示后端的安全错误说明，不能一律归因为模型配置。

任务历史接收预算为 4 MiB 个 JS 字符，覆盖合法冲突说明的最坏 JSON 转义；不能因正常历史超过较小前端门限而丢弃整个状态响应。

任务错误与 HTTP 请求错误分开：最新任务的安全说明由 `text-jobs-failure` 传入消息提炼页，任务成功或页面清理时清除。请求失败仍由 `text-jobs-error` 呈现。这样 HTTP 200 返回 failed 任务时，也能在发起提炼的页面看见原因。

配置表单具有 dirty 状态，后台刷新不能覆盖用户正在填写的字段。Key 提交后清空输入框，读取配置只得到 has_api_key；完整加密与共享并发见 [模型调用](模型调用.md)。

## HTTP 与权限

`/spaces/{space}/knowledge/` 下的 navigation、links、memory 为 POST 读取接口，jobs 提供 GET 状态与 POST 创建。它们使用 Web Cookie 和既有同源校验，不接受 Agent 密钥代替登录。memory 路由仅支持当前公开正文，不把事件详情或修订历史混入该入口。

`/system/text-model` 及其 test／disable 子接口另外检查实例管理空间。前端隐藏按钮不是权限检查的替代。

## Provider 表单

连接配置位于两个用途上方，已有 Provider 默认显示名称、地址与 Key 状态，点击编辑才展开敏感表单；新增时展开。已有选择、是否新增和表单显隐分别维护：新增或收起不清空原服务商选择，收起后继续展示其真实地址和 Key 状态；点击“继续新增”恢复未保存字段，编辑或选择已有服务商则载入其已保存连接。新增提交不携带已有选择的 ID，不能把草稿误写到已有连接。用途表单只有 Provider 选择与模型参数，Key 不在两个表单间复制。保存成功折叠并给反馈，错误保留在原表单；退出／切页清空待提交 Key 和请求代次。自动整理的运行参数默认折叠，启用／暂停和保存结果明确可见。

[Provider／整理设置控制器](../web/src/provider_browser.rs)、[表单组件](../web/ui/provider-settings.slint)。

Provider保存后若用途表单有未提交草稿，重新读取服务版本但不覆盖字段；只有用途本身的基线未变才更新expected_revision。模型、Provider绑定、并发等用途设置已在其他位置改变时保留草稿并提示冲突，用户可明确“重新载入配置”放弃草稿。重新载入是独立加载状态，避免轮询吞掉恢复操作。新保存文本模型后同步读取自动设置，不能继续显示初始化前的暂停状态。
