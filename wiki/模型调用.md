# 模型调用、配置与用量

[返回 Wiki](README.md) · [配置表](数据模型.md#text_model_settings) · [后台任务](后台任务.md)

Embedding 与文本模型是独立用途，共用实例级 Provider 的地址和 API Key；两种模型均为可选能力。初始管理空间可以通过 Web 管理，Agent MCP 密钥不因此获得系统设置权限。

## 两类模型的职责

| 模型 | 用途 | 未启用时 |
| --- | --- | --- |
| Embedding | 记忆向量索引与查询向量 | 继续关键词检索 |
| 文本 LLM | 主题整理和选定消息提炼 | 继续人工记忆、引用和主题导航 |

Embedding 的模型名、维度和编码方式构成索引身份，身份变化启动新代际重建；地址和 Key 不参与身份。文本模型不建立向量代际，修改其配置会阻止旧整理任务写回。向量机制详见 [模型设置与索引重建](../docs/模型设置与索引重建.md)。

## Provider 与用途绑定

系统设置先添加“模型服务商”，再为文本整理和语义检索选择 Provider 与模型。一个 Provider 保存一次规范化地址和加密 Key；同网站不同账号可建不同 Provider。用途各自保留模型名、并发、启用状态与专业参数，日用量和同名模型并发仍沿用原统计口径。

新页面只提交 provider_id，不重复提交 URL 和 Key。连接测试在用途表单中执行，Provider 保存本身不猜测可用模型；文本测试使用虚构 probe、向量测试验证维度与批量协议。测试通过只说明连接／协议可用，不衡量整理质量。

Provider Key 使用原实例根私钥派生的认证加密能力保存，绑定独立 credential_id；公开配置只有 has_api_key。修改地址必须重新提供 Key 或明确选择无需 Key。同地址留空保留原 Key，配置修订防止并发覆盖；兼容入口复用Key时只解析一次真实连接，用同一快照的地址校验该Key，不把旧用途行的地址与动态Provider凭据混合。HTTP 不跟随重定向。实例启动验证 Provider 根密钥标识，错钥拒绝启动，原私钥不能丢弃。

Provider 连接变化同步增加绑定的文本配置版本和向量连接修订，阻止旧在途结果写回；同 Provider 的两个用途随下一次调用使用新 Key。地址／Key 不参与向量身份，不触发向量重建。名称修改不影响业务调用；模型／版本／维度变化仍沿原确认和代际流程。

升级先执行新增表与可空绑定迁移，再在根私钥验证后幂等回填当前活跃连接。规范化地址和解密后的 Key 完全相同才合并，绑定后清除旧用途行的 Key 密文；旧字段保留用于兼容旧 HTTP 客户端和未绑定历史记录，运行时优先 Provider。旧客户端的直接连接提交仍可形成未绑定配置，下次启动再回填；新页面始终使用绑定。不会自动按站点推断账号一致，也不会因 Provider 合并重建向量。

文本模型的输出预算属于用途，不属于 Provider；保存、连接探测与后台任务均使用同一预算。推理模型可能把思考 Token 计入供应商的 max_tokens，过小会以未完整结束失败且不发布；提高预算仍需遵守服务商／模型限制。文本模型设置与自动整理设置分别有版本；升级旧文本配置保持自动整理暂停，新配置默认初始化启用，详见 [后台任务](后台任务.md)。

## 请求协议与限制

文本模型使用现有 reqwest 直接调用 `{base_url}/chat/completions`，发送固定系统说明和有限 JSON 快照，不提供可执行工具列表。

| 项目 | 当前值 |
| --- | --- |
| 输出协议 | `response_format: json_object`，非流式 |
| 输出 Token | 默认 `max_tokens: 16384`，文本模型高级设置可调 1024～65536 |
| 连接超时／HTTP 超时 | 5 秒／120 秒 |
| 响应体上限 | 512 KiB |
| 完成条件 | `finish_reason=stop`，输出为约定 JSON 结构 |
| User-Agent | `Chromie/` 加构建版本 |

JSON 可解析之后还有任务发布校验，不能把合法 JSON 当作可直接写库的命令。错误不回显原始模型响应或凭据。网络调用与并发等待位于业务事务外。

## 同名模型共享并发

`model_limits` 以模型名的 SHA-256 作为 model_key，保存并发上限和单调配置版本；同名模型在当前进程共享额度，不按业务、空间或索引代际另外建池。上限为 1～64，默认 4。

运行时用互斥计数、FIFO admission、Notify 和 RAII Permit 控制调用。取消等待或调用结束会释放位置，动态缩容不会取消在途调用，而是等占用回落后再放行。文本模型等待额度最多 15 秒，超时作为可重试的 model_busy。

配置版本用于避免旧设置把新上限改回去，embedding 和文本设置写入复用管理配置锁。当前容量计数位于服务进程内；多个服务进程各自计算占用，不提供分布式全局并发限制。

## 日用量

`model_usage_daily` 按 UTC 日期与请求模型名累计 `request_count`、`total_tokens`、`failed_count`、`unknown_usage_count`，不保存逐次调用正文。模型名是当前归并维度，不另外按空间或服务地址分账。

读取响应中的 total_tokens，缺失时尝试 prompt_tokens＋completion_tokens；供应方未提供用量时记 unknown，不把未知当作零 Token 的确定事实。排队未发送不计请求，连接测试会真实调用模型并计入用量。

统计是尽力记录：写入超时或失败只记有限日志，不重发已经得到结果的模型请求。因此它不是精确计费账单。请求失败与任务业务失败也分开：模型正常返回后因来源／修订等发布校验被拒绝，体现在任务状态，不一定增加模型请求失败数。
