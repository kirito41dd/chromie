# 数据模型

[返回 Wiki](README.md) · [架构与数据流](架构与数据流.md) · [数据库开发流程](../docs/数据库开发流程.md)

MySQL 8.4 是权威源。结构由 [SeaORM Migration](../migration/src/lib.rs) 演进，执行后生成 [Entity](../src/entity/mod.rs)；API DTO 与持久化 Model 分开。以下记录关键字段和约束，完整列定义以迁移为准。

UUID 在数据库中通常存为 `BINARY(16)`，对外使用 UUID 字符串；时间使用 UTC `DATETIME(6)`。空间内部 UUID 与人可读 `slug` 分开，修改 slug 不更换记忆身份。空间内对象关系优先使用包含 `space_id` 的组合键。

## 记忆主干

`memories` 保存 `current_revision`、创建／更新时间、`forgotten_at` 和创建 Agent；`memory_revisions` 保存正文、`project_key`、`change_reason`、操作者和创建时间。正文与更正理由可空，用于遗忘清理及有限历史压缩。正式正文上限为 16000 UTF-8 字节，更正理由上限 4000 字节。

新增 `memory_type VARCHAR(16) NOT NULL DEFAULT 'note'`，支持 `note`、`topic` 与 `topic_alias`。类型属于修订，普通记忆转为主题也追加版本。旧行保持 `note`，不扫描或改写旧正文。

`memory_sources` 表达“这个修订依据哪些消息”，`memory_links` 表达“这个修订指向哪些记忆”；两种 ID 不能混用。回执比较规范序列化输入的摘要，同一请求 ID 不接受不同参数。

## memory_links

| 字段 | 类型／可空性 | 含义 |
| --- | --- | --- |
| `space_id` | `BINARY(16) NOT NULL` | 所属空间 |
| `memory_id` | `BINARY(16) NOT NULL` | 源记忆 |
| `revision` | `INT NOT NULL` | 源修订 |
| `target_id` | `BINARY(16) NOT NULL` | 目标记忆 |
| `relation` | `VARCHAR(16) NOT NULL` | `reference` 或 `derived_from` |
| `target_revision` | `INT NULL` | 普通引用为空，派生依据为正数修订 |

主键包含源修订、目标与关系类型。同一修订最多 32 条关系由业务层校验。反向索引为 `(space_id, target_id, memory_id, revision)`；当前迁移没有另外增加主题类型索引。

三组复合外键分别连接源 `memory_revisions`、目标 `memories` 和目标 `memory_revisions`。普通引用的目标修订为空，不固定版本；应用层同时校验关系枚举、目标存活和派生环。数据库外键不替代这些领域规则。

迁移依据：[memory_graph](../migration/src/m20261111_134801_memory_graph.rs)。读取和遗忘语义见 [记忆与关系](记忆与关系.md)。

## text_model_settings

当前使用 `id=1` 的实例级文本用途，新增可空 `provider_id BINARY(16)` 绑定 Provider，不按空间分别保存模型配置。

| 字段 | 类型／可空性 | 含义 |
| --- | --- | --- |
| `id` | `TINYINT UNSIGNED` | 主键，当前固定为 1 |
| `revision` | `BIGINT NOT NULL` | 逻辑配置版本 |
| `credential_id` | `BINARY(16) NOT NULL` | 凭据加密标识，与配置版本分离 |
| `enabled` | `BOOLEAN NOT NULL` | 是否启用 |
| `base_url` | `VARCHAR(2048) NOT NULL` | 规范化接口地址 |
| `model_name` | `VARCHAR(256) NOT NULL` | 请求中的模型名 |
| `key_cipher` | `BLOB NULL` | API Key 密文 |
| `key_nonce` | `BINARY(12) NULL` | 加密 nonce |
| `key_id` | `VARCHAR(128) NULL` | 实例根密钥标识 |
| `updated_at` | `DATETIME(6) NOT NULL` | 更新时间 |

新增 `max_output_tokens INT UNSIGNED NOT NULL DEFAULT 4096` 保存文本用途的输出预算；该历史migration不修改，当前应用新配置默认16384，已有配置保留。应用校验 1024～65536，变更会推进配置修订并阻止旧任务发布。

最大并发保存在共享的 `model_limits`，不在此重复存一份。三个 Key 字段全部为空表示无需 Key；读取配置只返回 `has_api_key`。加密与变更流程见 [模型调用](模型调用.md)。

## knowledge_jobs

| 字段 | 类型／可空性 | 含义 |
| --- | --- | --- |
| `space_id`、`id` | `BINARY(16) NOT NULL` | 联合主键；id 使用提交方 request_id |
| `kind` | `VARCHAR(16) NOT NULL` | `organize` 或 `extract` |
| `config_revision` | `BIGINT NOT NULL` | 创建任务时绑定的文本模型配置版本 |
| `state` | `VARCHAR(16) NOT NULL` | 任务状态 |
| `payload` | `JSON NULL` | 有限输入快照，包含资料正文 |
| `result` | `JSON NULL` | 产物 ID、冲突说明、安全错误说明与内部请求摘要 |
| `lease_owner` | `BINARY(16) NULL` | 本次执行的随机标识 |
| `lease_expires_at` | `DATETIME(6) NULL` | 租约截止时间 |
| `attempts` | `INT UNSIGNED NOT NULL` | 领取执行次数 |
| `run_after` | `DATETIME(6) NOT NULL` | 最早运行时间 |
| `created_at`、`updated_at` | `DATETIME(6) NOT NULL` | 创建与更新时间 |
| `last_error` | `VARCHAR(64) NULL` | 稳定错误代码 |

到期扫描索引为 `(state, run_after)`，空间历史索引为 `(space_id, created_at)`，空间外键连接 `spaces.id`。公开任务结果去除内部 `request_hash`，不返回 `payload`。

任务快照是普通 JSON，不是 Secret 密文存储。完成或终止后清理输入快照；遗忘操作会进一步清空本空间任务副本和结果。状态与生命周期见 [后台任务](后台任务.md)。

两张新表的迁移依据：[knowledge_jobs](../migration/src/m20261111_135824_knowledge_jobs.rs)。这两条新增迁移的 `down` 显式拒绝自动删表／删列，避免把降级操作变成数据清理；后续结构变更新增向前迁移。

## model_providers

UUID 主键，name、base_url、revision 和创建／更新时间；credential_id、key_cipher／key_nonce／key_id 保存独立加密凭据。两种用途通过可空 provider_id 绑定，应用在管理锁内检查引用，公共接口不返回密文或原文。旧用途连接字段保留作兼容，绑定后以 Provider 为准。

## organization_settings

实例单行 id=1，revision、enabled、batch_size、interval_seconds、daily_limit 控制调度；usage_date／attempts_today 在 UTC 跨日重置，next_run_at 限制入队频率。预算计领取尝试，不按空间重复建立额度池。旧实例无行视为暂停；配置更新保留当日已消耗次数。

## organization_items

组合主键 space_id／memory_id，外键指向相同空间的 memories。revision 为本批次实际读取的当前修订，config_revision 供失败重排，state 为 queued／done／failed／pending；job_id 关联所属知识任务，run_after 为退避截止，last_error 仅代码，completed_at 为完成时间。不存另一份记忆正文。当前修订与进度行对应后，才能统计为已完成。

knowledge_jobs 新增 automatic，旧任务默认 false。自动信息持久化在任务快照供恢复与发布复核，但不发送给模型。新增结构由 [Provider 与进度迁移](../migration/src/m20261112_120000_providers_organization.rs) 管理，实际执行后反向生成 Entity；不删旧表或重写历史迁移。

## 对话增量进度与标题

[m20261113_000001_conversation_extraction](../migration/src/m20261113_000001_conversation_extraction.rs) 增加上述三张表，并为 organization_settings 增加 extraction_enabled（默认 false）和 last_kind。既有原始事件无需回填：未有进度行即待处理，done 不因模型切换重置；旧标题不存在时使用首条用户消息摘录。无历史正文、密文或私钥改写。

conversation_key 是带空间和可空 Agent 来源的身份元组 SHA-256（32 字节），不是标题摘要。metadata.revision 用于手动命名和模型响应的并发隔离；history 保存变更前后可追溯的各个已采用标题。extraction_items 以来源事件的空间组合外键防止悬空，job 索引服务于原子完成／释放批次；run_after 是 UTC 失败冷却时刻。

先在独立 MySQL 执行迁移，再用既定 SeaORM CLI 参数反生成三张新表及设置 Entity；无启动期 schema sync。旧库保留 memory／Secret／修订／来源等全部数据。遗忘会清理派生标题历史，事件进度保留且遗忘来源不再入队，细节见 [后台任务](后台任务.md)。

后台首次发布与自动更正会在现有 `write_receipts` 中登记内部 `background_revision` 操作，固定目标及修订。该标记不能由 MCP 参数伪造，用于判断历史证据是否允许修订；手动更正仍有当前修订时间屏障。主题合并只新增 `topic_alias` 修订与普通引用，无新增表；别名校验终点、空间、范围和环，随有效入口遗忘，不参与导航、看板和召回。

## 实际使用结果与维护进度

[20261117 迁移](../migration/src/m20261117_000001_usage_maintenance.rs) 扩展 `recall_items`：`use_outcome`、`use_reason`、`used_at` 保存一次原召回条目的 Agent 使用观察，与 useful/evaluated_at 独立。使用修订取该条目的 revision，Agent取父 recall_runs；不接受调用方伪造。没有报告为未知，unverified 可升级为最终结果；最终报告固定，相同重放幂等，不同结果整批冲突。当前修订聚合 used/succeeded/outdated/environment_blocked/unverified，历史召回计数不变。遗忘保守清空该空间的 use_reason 与所有后台输入/结果，保留非正文结果枚举，隐藏已遗忘记忆。

`organization_settings` 新增 maintenance_enabled（默认false）、maintenance_interval_hours（默认24）。`maintenance_items` 是周期进度，不是原始事件消费游标：revision、config_revision、state、job_id、requested_at、run_after、completed_at、last_error、updated_at，外键固定当前空间记忆。completed_at 为任务输入覆盖到的边界；requested_at 更晚时不能判完成。按空间/state/run_after建索引；实体由真实 MySQL 执行迁移后生成。

## 有限历史与自动复核

本轮无表结构变更。旧待确认建议的重新核对信息保存在 knowledge_jobs 快照的 pending_review，原结果 decision 的 resolution／review_job_id 表示归宿。普通正文自动修订仍使用既有更正事务和 write_receipts。历史压缩保留 memory_revisions 行以承接统计外键；详细保留规则、任务摘要结构与保护范围见 [历史保留](历史保留.md)。
