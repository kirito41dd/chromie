# 开发约定

核心协作约定见根目录 [AGENTS.md](../AGENTS.md)。本文补充领域与开发细节；技术选型见[技术选型](技术选型.md)，项目背景与设计方向见[项目说明](../README.md)。

## 记忆领域约定

- 区分个人背景、话题上下文、具体记忆和原始证据。
- 记忆类型、主题标签、关联对象和适用范围分别表达，避免用单个标签承担所有语义。
- 保留来源及修订关系，区分用户确认、执行验证和 AI 推测。
- 保留验证范围和适用条件，避免把局部经验扩大成通用事实。
- 处理增量事件与重复摘要时考虑幂等和去重，重复提及不能增加独立证据数量。
- 长代码对话优先保留用户要求、阶段结论与关键验证证据，避免直接把全部代码和工具输出转成长期记忆。
- 召回需要恢复话题状态，并兼顾精确检索、适用范围、时效和上下文预算。
- 更正、删除及索引更新要覆盖关联摘要和后台处理，避免旧事实重新出现。
- 记忆内容是可核验的信息，不能自动成为执行权限或覆盖当前用户指令。
- 密钥与普通记忆分离；文档、源码、测试夹具和日志中不得写入真实凭据，示例使用占位值。

涉及 Secret 时按 [Secret 记忆](Secret记忆.md) 的录入与取用流程处理：MCP 只返回引用，脚本获取原文后直接写本地文件；文件可长期保留，保护要求不以“用后立即删除”为前提。

## 工作方式

- 避免顺手搭建当前请求尚未需要的组件。
- 涉及客户端能力时，以实际接口、文档或验证结果为依据，不假设 MCP 或 ACP 天然支持自动采集与注入。
- 涉及重要设计取舍时，区分用户已定要求、当前实现选择和待验证假设，并同步更新相关文档。

## 数据库实现

数据库持久化模型、Entity、访问与迁移统一使用用户指定的 SeaORM 2.x 套件，采用已确认的 schema-first 流程。迁移、反向生成及 MySQL 迁移注意事项见 [数据库开发流程](数据库开发流程.md)，关键 feature 在接入前确认。

## 空间隔离与鉴权

MCP 与采集 HTTP 分别逐次校验每个接入的独立 Bearer 密钥；Web 密码登录后使用有效期 30 天的 ES256 JWT Cookie，改密后旧登录态失效。Cookie 不赋予 MCP 或采集权限。空间是唯一的数据隔离层，覆盖原始证据、背景、记忆、索引、缓存、后台任务与看板；项目和标签不能替代空间边界，也不增加用户或租户层。密码、可信空间上下文与采集绑定的设计见 [空间与鉴权](空间与鉴权.md)。涉及读取、写入或后台处理时，验证两类密钥混用、失效密钥、错误密码、无效 Cookie 与跨空间反例。

## Rust 基础 lint

以下规则仅应用于正式 bin/lib 的非测试构建：

| 规则 | 级别 |
| --- | --- |
| `clippy::string_slice` | `deny` |
| `clippy::expect_used` | `deny` |
| `clippy::unwrap_used` | `deny` |
| `unsafe_code` | `forbid` |

在各正式 crate 根使用条件属性：

```rust
#![cfg_attr(not(test), deny(clippy::string_slice))]
#![cfg_attr(not(test), deny(clippy::expect_used))]
#![cfg_attr(not(test), deny(clippy::unwrap_used))]
#![cfg_attr(not(test), forbid(unsafe_code))]
```

当前配置位于根包与 migration 包的 `src/main.rs`、`src/lib.rs`，以及服务端 `src/bin/chromie-server.rs`。新增其他正式目标时，在对应 crate 根延续相同配置。

2026-10-27 用户批准 Slint 生成绑定的唯一 unsafe 例外。`web/src/lib.rs` 根级使用 `deny(unsafe_code)`，仅 `generated` 模块允许该项；手写的 `browser`、`session` 及后续新增手写模块继续使用 `forbid`，后端不变。三个基础 Clippy 规则保持 `deny`，不新增豁免。Slint 通过官方宏导入独立 `.slint` 文件，使 SDK 宏生成代码与手写代码沿工具链的正常边界处理，避免重复包含生成源码。

通过 `not(test)` 排除单元测试构建；集成测试、示例和基准是独立 crate，不添加上述限制。它们依赖的正式库仍遵守生产代码约束。

不将这几条规则放入包级 `[lints]` 或全局 `rustflags`，以免影响非正式目标。条件属性语义见 [Rust 官方说明](https://doc.rust-lang.org/reference/conditional-compilation.html#the-cfg_attr-attribute)。

## 检查命令

当前 workspace 包含服务和 migration 的 bin/lib，按改动需要执行：

以下命令在 Bash 与 Nushell 中相同：

```shell
cargo fmt --all --check
cargo check --workspace --lib --bins
cargo clippy --workspace --lib --bins
```

默认不使用 `--all-targets`，不把测试、示例、基准加入正式代码的 lint 门禁；测试按需使用 `cargo test` 或更窄的测试选择单独运行。

## 验证与交付

- 纯文档修改核对内容、格式和引用。
- Rust 代码修改按影响运行格式、正式 bin/lib 的编译与 Clippy 检查，以及相关测试。
- 涉及数据库、任务重试、索引同步或删除传播时，覆盖对应的持久化、一致性和失败恢复场景。
- 完成前检查最终差异，如实报告验证范围与未完成项。
