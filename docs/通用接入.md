# 通用接入

适用于自行配置客户端的用户。MCP 负责记忆读写；可选 hook 调用我们提供的 Chromie bin，上传由 bin 完成。客户端只负责注册 hook，以及必要的输入字段转换，不需要自己实现 HTTP、鉴权、UUID 或离线重试。可以只配置 MCP。

## MCP

在 Web 创建接入，进入“通用接入”，将当前空间的地址和 MCP 密钥配置到客户端：

```http
POST https://你的Chromie服务/spaces/work-notes/mcp
Authorization: Bearer 填入MCP密钥
```

传输方式为 Streamable HTTP，具体配置字段由客户端决定。先完成工具发现，再保存并召回一条用户允许的虚构测试记忆。日常记忆使用规则由 MCP instructions 和工具描述提供。

## hook 调用采集程序

先用接入页的统一安装命令安装 CLI，再运行：

Bash：

```bash
"$HOME/.local/bin/chromie" init --url https://你的服务地址 --space work --agent generic --data-dir /绝对私有目录/chromie
```

Nushell：

```nu
^($nu.home-dir | path join ".local" "bin" "chromie") init --url "https://你的服务地址" --space work --agent generic --data-dir "/绝对私有目录/chromie"
```

在浏览器登录、核对确认码并选择接入后，CLI 直接保存 `/绝对私有目录/chromie/client.json` 并检查 MCP；通用客户端仍自行配置 MCP 和 hook 注册格式。旧包与 JSON 仍可导入，但不再作为推荐的安装流程。

在客户端的用户消息提交、助手最终回复 hook 中注册同一条命令。支持 shell 命令时可直接使用；exec 形式把环境变量、程序和参数分别填入客户端对应字段：

Bash：

```bash
CHROMIE_QUEUE_DIR="/私有目录/chromie/queue" "$HOME/.local/bin/chromie" capture --config "/私有目录/chromie-client.json"
```

Nushell：

```nu
with-env {CHROMIE_QUEUE_DIR: "/私有目录/chromie/queue"} { ^($nu.home-dir | path join ".local" "bin" "chromie") capture --config "/私有目录/chromie-client.json" }
```

客户端通过 stdin 向程序传入 JSON。与 Codex UserPromptSubmit／Stop 输入兼容时直接使用，无需转换；字段不同时，只在本地转换成下面的通用消息，再通过管道交给相同命令：

```json
{
  "session_id": "客户端会话ID",
  "role": "user",
  "body": "消息正文",
  "turn_id": null,
  "project_key": null
}
```

role 仅为 user／assistant，助手消息只传最终回复。turn_id 和 project_key 可省略，项目未指定时可使用 CHROMIE_PROJECT；正文最多 60,000 字节，其他标识最多 128 字节。空消息跳过。通用输入的 stdout 仅为 `{}`；若客户端要求其他输出格式，由薄包装处理。原生未知事件不会被当作通用消息采集。

bin 自动读取私有配置的 hook_key、生成事件 UUID 和时间，完成 HTTPS 上传、私有队列暂存；不需要在输入中提供空间、Agent ID、密钥或事件 ID。网络恢复后使用同一配置和队列补传：

Bash：

```bash
CHROMIE_QUEUE_DIR="/私有目录/chromie/queue" "$HOME/.local/bin/chromie" flush --config "/私有目录/chromie-client.json"
```

Nushell：

```nu
with-env {CHROMIE_QUEUE_DIR: "/私有目录/chromie/queue"} { ^($nu.home-dir | path join ".local" "bin" "chromie") flush --config "/私有目录/chromie-client.json" }
```

Bash 可用 `export CHROMIE_CAPTURE=off` 暂停采集；Nushell 使用 `$env.CHROMIE_CAPTURE = "off"`。队列目录 0700、文件 0600；补传保留原 UUID 与时间，并校验原空间与接入，不会在换接入后改投。先用虚构消息检查 bin，再在真实客户端发送新消息核对 Web 来源与上传时间。仅测试 bin 上传成功，不等于原生 hook 已触发。

## 底层 HTTP 协议参考

下面是 bin 内部使用的上传协议，仅供自行实现上传器或排障参考；常规 hook 接入使用上面的采集命令即可。

```http
POST https://你的Chromie服务/spaces/work-notes/events
Authorization: Bearer 填入hook上传密钥
Content-Type: application/json
X-Chromie-Agent-Id: 填入当前接入的Agent-ID

{
  "id": "01900000-0000-7000-8000-000000000001",
  "client_type": "other",
  "session_id": "客户端会话ID",
  "turn_id": null,
  "role": "user",
  "body": "虚构测试消息",
  "project_key": null,
  "occurred_at": "2026-10-29T00:00:00Z"
}
```

示例中的空间、ID、时间和消息须替换为实际值；Web 会提供当前空间的 URL 和 Agent ID。

| 字段 | 约定 |
| --- | --- |
| id | 每条消息生成一个 UUID，推荐 UUIDv7；失败重试复用完整原请求，不能只保留 ID 却更改时间或正文 |
| client_type | 当前协议要求的兼容字段，可填 other；服务端用接入记录覆盖，不作为可信的软件身份 |
| session_id | 客户端会话标识，最多 128 字节 |
| turn_id | 可选轮次标识，最多 128 字节；无此信息时用 null 或省略 |
| role | 仅 user 或 assistant；assistant 表示最终回复，不上传中间推理和工具输出 |
| body | 非空消息正文，最多 60,000 字节；不要包含接入密钥或 Secret 原文 |
| project_key | 可选项目标识，最多 128 字节；无此信息时用 null 或省略 |
| occurred_at | 消息实际发生时间，RFC3339 格式，须带时区 |

Authorization 必须使用独立的 hook 上传密钥，不能使用 MCP 密钥或空间密码。身份由服务端鉴权确定，不能在正文添加 agent_id 来指定来源；未知字段会被拒绝。X-Chromie-Agent-Id 是可选的目标校验，建议发送；它必须与上传密钥所属接入一致。

HTTP／HTTPS 均支持，TLS 由部署或网关提供，不按网络位置限制。密钥由本地脚本从私有配置读取，不放在命令行参数、消息正文、对话或日志中。Web 下载文件包含 mcp_key 与 hook_key，先保护文件权限再使用，文件可长期保留在本人私有目录。

## 重试与验证

成功返回 HTTP 200，响应包含 event_id，以及 stored 或 duplicate 标记。同一接入重试相同事件不会重复保存；相同 ID 对应不同内容会返回 409，不能不断生成新 ID 掩盖冲突。401 时检查密钥用途、接入启停与 Agent ID；400 时检查字段、时间、长度和角色。临时网络失败可在本地私有队列保留原事件后补传，不将队列内容输出给模型。

先上传一条明确标记为虚构的测试事件，核对 Web 的最近上传时间与当前接入来源；再通过真实客户端发送新消息，验证 hook 是否实际触发。测试上传只证明 HTTP 链路可用。

客户端 hook 的注册方式、输入字段、超时和返回格式按客户端官方文档配置。现有 chromie capture 同时接受 Codex 兼容载荷和上述通用消息；必要的适配仅转换输入，不重复实现上传与凭据处理。

原始采集不会自动生成可召回记忆。长期结论仍由 agent 使用 remember 保存；Secret 存取走独立流程，见 [Secret 记忆](Secret记忆.md)。
