# 持续集成与发布

GitHub 上游为 [kirito41dd/chromie](https://github.com/kirito41dd/chromie)，镜像目标为 `docker.io/kirito41dd/chromie`。工作流配置在 [ci.yml](../.github/workflows/ci.yml) 和 [release.yml](../.github/workflows/release.yml)，官方 Actions 固定到经过核对的提交，不自动跟随主版本标签变化。

## 首次准备

1. 在 Docker Hub 的 `kirito41dd` 命名空间创建公开的 `chromie` 仓库。
2. 创建用于发布的 Docker Hub Personal Access Token，授予读取和写入权限即可。
3. 在 [GitHub Actions Secrets](https://github.com/kirito41dd/chromie/settings/secrets/actions) 中保存 `DOCKERHUB_TOKEN`，值为该 Token。不要提交到源码、构建参数或聊天中。
4. 确认 GitHub Actions 已启用。最终发布 job 单独申请 `contents: write` 上传 GitHub Release，其他 job 默认只有源码读取权限。

使用 GitHub 账号登录 Docker Hub 不会自动给 Actions 发布权限。本方案由 GitHub 构建后推送，不使用 Docker Hub 的旧 Automated Builds；组织账号如需改用 OIDC，应另行配置仓库／标签信任规则。[Docker 官方说明](https://docs.docker.com/build/ci/github-actions/)、[旧自动构建退役说明](https://docs.docker.com/docker-hub/repos/manage/builds/setup/)。

## 日常检查

向 main／master 提交、发起 PR，以及发行流程调用时执行：

- 正式 bin/lib 的格式、编译与 Clippy，另检查 Wasm 目标。
- 不依赖真实服务的 Rust 库单元、浏览器桥接、CLI 安装器和发行材料测试。
- Dockerfile 与源码 Compose 的静态检查。

PR 不登录 Docker Hub，也不发布镜像。真实 MySQL 集成测试仍须单独使用隔离库；发行镜像另跑独立 Compose 端到端验收。普通 CI 不取得生产配置或模型密钥。

## 构建演练

在 GitHub Actions 选择“构建与发布”并手动运行。手动触发只构建四个平台 CLI、两种架构镜像，并用虚构资料验收，不推送镜像、不创建 Release，也不要求 Docker Hub Token。

四个平台为 Linux x86_64／ARM64 与 macOS Intel／Apple Silicon，使用对应原生 runner。Linux CLI 在 Rust bookworm 容器内构建，保持 glibc 兼容基线；macOS 在对应架构执行版本检查。CLI 汇集后校验 SHA-256、文件格式及实际架构，再进入镜像。

## 发布稳定版本

先将根 Cargo.toml 的版本设为准备发布的稳定版本，完成审查和提交。入口接受 `v主版本.次版本.修订号`，要求与 Cargo 版本一致。以下命令在 Bash 与 Nushell 中相同，示例版本需与实际源码一致：

```shell
git tag v0.1.0
git push origin v0.1.0
```

流程依次执行检查、四平台 CLI 构建、两种 Linux 架构镜像构建、独立 Compose 验收。验收包含首次初始化、登录、MCP／hook、Secret、客户端取用、重启、改密和原钥恢复。配置、数据库、根私钥及原始命令日志留在临时测试目录，不上传为发行材料。

每个平台通过后先推送本次运行的临时标签；两个平台全部成功后才创建固定版本的多架构镜像并更新 latest。固定版本内容不同则拒绝覆盖，重跑旧版本不会回退到比当前 latest 更低的版本；读取仓库状态失败也不会当成首次发布。上传源码不等于发布镜像，只有版本标签触发正式发行；缺少 Token 会在编译前明确失败。

GitHub Release 附带只拉取镜像的 `compose.yaml`、四平台 CLI 压缩包（程序／校验值／许可）、中文使用说明和 `SHA256SUMS`。Compose 固定到本次版本，不含 build 或开发数据。

用户下载 Release 的 Compose，在独立目录运行。以下命令在 Bash 与 Nushell 中相同：

```shell
docker compose pull
docker compose up -d
docker compose exec chromie chromie-server initial-login
```

Compose 按宿主架构选择镜像；镜像内携带四个平台的 CLI，Web 安装器按用户设备下载，无需用户编译客户端。

## 当前验收边界

本地可检查工作流语法、发行材料、校验器以及本机架构的构建和容器流程。GitHub 各原生 runner、Docker Hub 推送和 Release 上传必须在首次远程运行中验收；配置写好不等于镜像已经发布。首次发行成功前，继续使用仓库的源码 Compose。
