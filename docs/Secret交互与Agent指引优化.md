# Secret 交互与 Agent 指引优化

2026-10-29，基于真实测试对话按用户确认的范围顺序实施。原始消息采集保持现状，不修改过滤、脱敏、保留或遗忘行为。

## 用户提前告知将提供密码

Agent 先引导用户不要将原文发入聊天，调用 `get_setup_guide(topic="secret")` 获取当前空间、接入和 Secret 权限状态。权限未开时给出接入管理入口，由用户开启；不代替用户扩大权限。

尚未提供原文时，用户在自己的终端运行 `chromie secret put --label '服务密码' --prompt`，由 CLI 隐藏输入并确认，直接使用本机接入文件里的 MCP 密钥，通过独立 HTTP 保存。Agent 只接收不含原文的回执与 Secret 引用。已经存在于私有文件的凭据使用 `--file`。已发原文且授权代存的流程见下节，不要求用户重新录入；原始消息照常采集，不宣称能追溯消除副本。

## 原文已主动提供并授权代存

2026-11-03 用户实测：已在对话提供测试 Grafana 密码和 Token，并要求 Agent 操作，仍被要求在终端手工隐藏输入。原指南一边允许“按当前授权处理”，一边笼统禁止写入脚本并要求用户输入，导致流程冲突。

现在区分两条路径：未提供原文时默认隐藏输入或已有私有文件；已主动提供且当前任务明确要求代存时，Agent 直接使用私有临时文件与 `secret put --file`，不反复确认或让用户重输。一次性本地工具输入可搬运已给原文，必要的中转脚本也仅放 0700 临时目录，载荷和脚本 0600，完成后清理自己创建的文件。Chromie 参数、公开说明、MCP、仓库和输出仍不带原文；服务端仍加密保存，权限开关继续校验。

这不取决于内外网，也不把凭据出现在历史或第三方文本中等同于代存授权。当前任务已经授权时直接执行；原始消息采集策略不变。MCP 初始化摘要、Secret 指南、工具描述、CLI 帮助、hook 路由和示例协作约定使用同一口径。

已用虚构密码和 Token 验证现有 CLI 文件代存，在本机与服务器更新指南；旧指南版本会返回新正文。原对话重新读取 `get_setup_guide(topic="secret")` 后即可继续使用此前主动提供且已授权的内容，无需重新发送密码。服务更新保留原数据、接入、实例根私钥和登录态；本次没有另开自然对话验证模型遵循率。开发验证方法见 [开发运行](开发运行.md)。

## CLI 与指南

- 新增 `secret put/get/update`，读取既有私有配置或当前接入环境；默认兼容 Codex CLI 初始化的配置位置。帮助不依赖数据库、配置或网络。
- 上传接受私有文件或隐藏输入；取用只写入私有文件，默认拒绝覆盖，显式 `--replace` 才替换。原文不写 stdout、日志或错误，不返回服务端错误正文；远程 HTTPS、禁止重定向、大小限制与当前空间引用检查沿用既有约定。
- 写操作生成并返回 request_id，失败后提示复用；不自动重新生成请求重试。保留修订检查和服务端幂等语义。
- `get_setup_guide` 增加有默认值的主题参数，分别返回 setup／secret／capture／diagnostics；空参数仍兼容原初始化指南。Secret 指南包含可执行 CLI 用法、HTTP 合约、权限状态和当前空间引用示例，不依赖用户机器存在项目源码。
- 用户已同意新增 `rpassword` 7.5.4（读取隐藏输入）与 `rustix`（提示前保护及恢复终端）。rustix 复用锁文件已有的 1.1.5，不升级其他依赖；手写代码保持 forbid unsafe。

## 召回与语义歧义

短缩写召回为空时，不能自动认定某一个展开含义；先结合当前任务，用服务名／操作入口／相关领域词少量补查，仍有歧义再澄清。确认后的服务别名、日志入口和可复用操作方式可以存为普通记忆，凭据原文只走 Secret。此次不增加 embedding，不改检索算法，不自动写入当前真实部署信息。

## 交付前发现的终端时序问题

文件模式、权限与 MCP 指南的实际服务验证已通过。重复 PTY 测试发现 rpassword 7.5.4 的 prompt_password 先输出提示，再在 read_password 中关闭回显；即时输入能触发回显窗口。不能通过给测试加延时来掩盖。

用户已确认增加 rustix。实现采用安全 termios API：显示提示前关闭 ECHO／ECHONL，完整覆盖两次输入及两次 rpassword 调用之间的间隙；成功时显式恢复，失败和取消时由守卫恢复。使用现有 Tokio 捕获 rpassword 发出的 SIGINT，使 Ctrl-C 可以完成清理；输入结束后继续监听 HTTP 等待阶段，取消时提示写入结果可能未知并要求复用 request_id。文件模式不修改终端或信号处理。

交付验证使用真实 PTY，在看到提示后立即写入，不添加输入延迟；成功、输入不一致、两次提示处 Ctrl-C、EOF、HTTP 失败和上传中取消均检查终端设置恢复。下载产物只在验证通过后替换。原始采集、真实凭据与实例密钥保持不变。

2026-10-30 验证通过：6 项 CLI 测试（含连续 12 次即时输入及真实 Nushell）、1 项真实 MySQL／MCP 存取流程、5 项安装器测试；47 块 Bash 与 47 块 Nushell 示例通过语法验证，正式 workspace bin/lib 的格式、check、clippy 通过。已更新本机服务、CLI 下载产物和已安装 CLI；接入配置保持原样，根私钥与既有指纹一致。新 MCP schema／instructions 需客户端重载或新开对话后使用。

## 录入上下文补全

2026-10-30 用户确认优化：用户通过 --prompt 只录入密码，服务、用途、环境和项目等公开背景由 Agent 整理。沿用现有 label／content（最多 256 UTF-8 字节）与项目范围，不新增字段或单独的说明表。

录入前，Agent 将已明确的信息放入 label 和可选 --project；不知道的字段不编造，也不让个人凭据自动继承当前代码项目。收到回执后，先核对同空间引用与 memory_id，并通过 get_memory 读取当前公开元数据。只在缺少已知背景时调用 correct_memory 更正同一条说明／范围；不重复 remember、不关联原始来源、不读取密码，不使用原文 PUT 更新元数据。已经完整或重复回执不制造修订。

回执的短路由也纳入现有 UserPromptSubmit 附加上下文，连同前置的 Secret 录入入口保持在 220 字符内；当前包含 UUID 的整段为 213 字符。它只说明入口，不复制完整指南或用户正文，也不改变事件上传、保留或队列语义。

补全使用当前读取的修订而非旧回执；冲突后比较最新内容，不静默覆盖其他写入。对象隐藏、不存在、引用不符或未发现密文时停止补全。说明修改不能改变 Secret 引用、载荷修订、nonce 或密文。若补说明失败，明确区分录入回执与说明状态，不让用户重复录入密码。

验证分为接口和自然对话两部分：接口覆盖补全后的召回、同对象更新、旧录入回执、重试幂等、无新增记忆及密文不变；自然对话应验证收到回执会主动核对、只补用户给出的公开信息，以及重复回执不再写入。未运行的对话验收不能以接口测试代替。

已验证：真实 MySQL／MCP 的补全、召回、旧回执与幂等流程通过，补全前后密文、nonce、载荷修订及记忆数量不变；原生 hook 输出测试确认附加上下文仍不含原消息和密钥。正式 bin/lib 的格式、check、clippy 及 49 块 Bash／49 块 Nushell 示例语法检查通过。
