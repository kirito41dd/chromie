# 模型设置与索引重建

2026-11-03。embedding 是可选能力，默认关闭。当前支持 OpenAI 兼容的浮点 embeddings 接口，默认模型名 text-embedding-v4、1024 维；服务地址和密钥由用户在自己的 Web 页面填写。

## 打开设置

登录初始管理空间后，顶部出现“系统设置”，地址为 `/spaces/空间/settings`。设置对整个后端生效，各空间的记忆和检索候选仍隔离。管理空间由内部 ID 绑定，改名不影响权限。系统设置要求 Web 登录 Cookie，MCP／hook 密钥和单独的空间密码请求头均不能代替登录态。

容器首次初始化自动绑定初始 personal 空间；已有容器升级从 config/initialized.json 中的原空间 ID 绑定，不重建空间、密码或根私钥。独立运行的开发服务可在私有环境文件设置 CHROMIE_ADMIN_SPACE 为已创建的空间标识，例如 demo；首次绑定后不能用更换该值静默转移管理权。未指定管理空间的旧开发实例继续使用关键词检索。

## 配置并启用

填写服务 Base URL（包含服务要求的 `/v1` 或兼容接口前缀）、模型名、API Key。服务地址指 Chromie 后端可访问的地址；模型部署在另一台机器时，不能把浏览器电脑的 localhost 当作后端地址。高级设置包含维度、实际模型版本、每批最多文本数、相似度下限及清除已保存 Key。

API Key 默认掩码，输入框留空表示沿用已有值；已有 Key 时，高级设置显示“移除已保存的 Key”，勾选并保存成功后才移除。配置和进度自动轮询更新，不提供额外刷新按钮，正在编辑的输入不会被轮询覆盖。Key 不写入 localStorage，后端使用实例根私钥的独立用途派生密钥加密保存。原根私钥和 MySQL 必须分别备份，丢钥不能通过重新初始化解决。

点击“保存并启用”时，后端先发送固定虚构文本，检查鉴权、返回数量、浮点数值与维度；通过后才保存配置并启动任务。测试不使用真实记忆。HTTP／HTTPS 均可配置，模型请求禁用重定向，错误不回显服务端正文或凭据。

所有模型 HTTP 调用统一携带 `User-Agent: Chromie/<构建版本号>`，包括连接测试、保存前验证、后台索引生成和召回查询。UA 仅包含产品名和版本号。

也可先点“测试连接”，单独验证当前表单，显示模型名、返回维度、验证的文本段数和耗时。测试使用同一套检查，但不会保存地址或 Key、启用模型、创建代际或登记重建任务；更换模型也可以先测再确认重建。Key 留空仍沿用已有值，刚输入的 Key 在测试后保留于当前表单内存，便于直接保存，离开页面清除。测试会产生一次模型请求，成功只证明这次接口与配置可用，不代表历史语料的召回质量或长期稳定性。

## 批量 embedding

高级设置的“每批最多文本数”允许 **1～10**，留空自动选择：`text-embedding-v4` 为 10，其他模型为 1。切换模型时清除旧覆盖，未知接口先保守使用单条，需要时自行增大并“测试连接”。测试和新连接保存前的验证会按当前批大小发送固定虚构文本，确认接口接受数组且结果对应完整，不使用真实记忆。

后台历史构建与新增／更正共用批量入口，只把同空间、同模型代际、同连接修订的当前待处理文本合在一个 HTTP 请求中；不等待凑满。23 条可分成 10＋10＋3，只有一条时立即发送一条。在线召回始终立即单条请求，不与后台凑批。Secret 仍只发送公开说明，不读取原文。

批大小是请求调度参数，不改变模型身份、向量或索引代际；仅修改此值直接保存，不调用模型、不重建、不重封装 Key。新代际不会继承旧模型的覆盖值，旧索引继续使用自己的设置。配置 API 的 `batch_size` 省略表示保留同身份覆盖值，`null` 恢复自动，整数表示覆盖；读取返回生效值 `batch_size` 与覆盖值 `batch_size_override`。

响应按 `index` 重排，严格检查结果数量、索引完整／唯一／范围以及每个向量的维度和数值。对应关系无效时整批拒绝，不把错位向量写入记忆；页面提示调小批大小。临时故障仍按各任务退避，批量协议错误暂停对应任务，修改批大小后自动恢复这些暂停项。向量逐条发布前仍复核租约、当前修订、遗忘与模型代际，批内一条更正或遗忘不会让旧结果复活。

一批 HTTP 占同名模型的一个并发名额。每日请求数和 usage 按请求累计一次，不把十段误算成十次请求，也不重复累加供应商报告的 Token；批量减少往返，Token 用量取决于实际文本，不承诺减少 Token。索引覆盖和失败数量仍按记忆条目计数。

## 召回相似度下限

高级设置的“相似度下限”标为专业参数，范围 0～1。这里使用余弦相似度，越大越接近；阈值越高，返回越严格，也可能漏掉有效记忆。输入框留空采用自动值，0 显式关闭过滤。旁边信息图标悬停可读说明，点击或键盘 Enter／空格可展开完整说明，Escape 收起；说明包含评测规模、收益和局限，触屏不依赖 hover。

自动推荐仅匹配已评测的 `text-embedding-v4 / 1024 / plain-v1` 且未声明其他版本，默认 **0.56**；其他模型／版本／维度没有已验证推荐值，自动状态不启用阈值过滤。模型名、维度、版本编辑时清除表单旧覆盖值，避免换模型后静默继承。需要自定义时应在确认模型身份后填入并验证。

推荐依据是 [阈值评测](检索阈值评测-2026-11-04.md) 的 3,000 条候选与 660 个查询：留出明显无关问题非空从 60/60 到 0/60，公开集 Hit@5 从 96/100 到 93/100，个人集保持 100/100。但近似无答案仍有 48/50 返回内容；相似度不能保证资料包含答案。这是缩减公开集与合成个人场景，不能泛化为所有线上查询零误召回。

阈值按代际保存，不参与向量身份；只改阈值或并发直接保存，不测试模型、不重建索引、不重封装 Key，也不重置后台任务。新模型构建期间旧模型沿用自己的阈值，新代际就绪后与其配置一起切换。配置仍使用管理空间登录态和修订冲突保护。

召回先取得两路候选，用本次同一个查询向量检查余弦，再按保留候选重新编号做 RRF；不会把 BM25 或 RRF 分数与 0.56 比较。BM25-only 候选按相同空间和 project/global 范围补分，不额外请求 embedding。完整查询去两端空格、转小写后至少两个 Unicode 字符且为公开正文连续子串的 BM25 命中豁免；不以零散关键词出现代替精确匹配。

模型未启用／故障时保持关键词检索；新记忆尚无向量、评分修订过期或补分故障时不因缺分删除关键词候选。Secret 只检查公开说明，原文不参加过滤。Web 调试响应的 `embedding.filter` 包含阈值、各路过滤计数、精确豁免、未评分关键词数和补分状态，只列最终交付对象的详情。

配置 API 的 `similarity_threshold`：省略沿用同模型覆盖值，显式 `null` 恢复自动，数字为自定义值（含 0 关闭）。读取返回生效值 `similarity_threshold`、覆盖值 `similarity_threshold_override` 和可空推荐值 `recommended_similarity_threshold`。旧客户端换模型并省略字段时不继承旧阈值。

## 模型 Token 用量

系统设置展示今日、近七日与累计已知 Token，以及最近七日的每日模型行。只统计 Chromie 后端发起的模型调用；连接测试（含保存前验证）、后台索引生成和召回查询一起计入，不统计 Codex 等 Agent 自身调用模型的消耗。

MySQL 按 **UTC 自然日 + 请求模型名** 一行累计 `request_count`、`total_tokens`、`failed_count`、`unknown_usage_count`，不保存逐请求流水、输入正文、地址或 Key。同名模型更换地址、Key、维度、版本或重建代际仍归入同一天的同一行；不同模型各自累计，换模和旧索引回收不清除历史统计。请求归入发起日，跨午夜返回也不移到次日。

- 每次出站请求尝试增加一次请求数，重试是另一次调用；无效本地配置在发送前被拒绝时不增加次数。
- 优先使用响应 `usage.total_tokens`，缺少时兼容 `usage.prompt_tokens`；两者不能相加。缺失、负数或无法识别的用量记为未知次数，不伪造零 Token。汇总数字只代表已知用量，页面同时说明未知请求。
- 收到 usage 后，即使向量格式／维度校验失败，或计算完成后任务因更正、取消而不再发布，也保留已报告的消耗。模型调用失败次数包含传输、HTTP 和向量协议校验失败；后续 Qdrant 发布失败不算模型调用失败。
- 统计采用数据库原子累加，避免并发覆盖。统计写入有短超时，失败不掩盖模型结果、不触发额外模型调用，也不重试无法确认是否已提交的累计。进程在返回后、入库前退出或数据库故障可能漏计，因此该统计不替代服务商账单。

升级前没有保存 usage 的调用不补算。统计为实例级数据，只对初始管理空间的 Web 登录态开放；未启用模型也可查看历史用量。最近明细最多展示 100 行，汇总覆盖全部记录。原数据库备份同时包含这些按日数据，不引入额外服务、计费配置或依赖。

启用会为全部空间当前有效记忆生成向量，后续新增、更正自动处理。输入仅取正式记忆正文；Secret 取公开说明，完全不读取其载荷。原始采集消息不会因为开启 embedding 自动变成记忆，也不参与这轮模型调用。搜索问题同样需要发送至该模型服务。

## 更换模型

模型名、版本、维度和编码方式决定向量代际。不同模型即使维度相同，也需要重建。服务地址和 API Key 属于连接信息，不进入向量身份；仅修改连接可沿用索引，但需要用户确认实际模型版本与编码方式相同，连接测试本身不能证明这一点。同名模型更新权重时，可在页面底部“索引维护”中选择“重建索引”。该操作只使用已保存的配置，不会夹带尚未保存的表单编辑。

更换模型、重建索引和停用语义检索均使用居中确认弹窗；危险操作按钮为红色，默认聚焦“取消”，支持 Escape 取消和 Tab 在弹窗内切换。弹窗说明全实例影响、调用费用或停用后的关键词回退，只有确认后才发起请求。后端创建新代际、分页扫描全部空间有效记忆的当前修订，同时接收新增、更正与遗忘；旧修订和遗忘内容不复活。旧模型仍可用时继续原检索，新索引追平当前数据后自动切换。旧模型不可用时回退关键词。

进度、游标和任务租约存于 MySQL，重启后继续。网络中断、超时、限流、上游 5xx／408 和索引服务临时故障会持续自动退避重试，间隔最长五分钟，不因超过五次失败而停止；旧版本已经停止的同类任务也会自动恢复。鉴权、格式或维度配置错误暂停对应任务，页面提示检查配置，保存有效设置后自动继续。页面展示自动重试数量和下一次尝试时间，无需用户盯着或点击“重试失败项”。进度按当前有效记忆及修订计算，不把重试次数当作完成条数。扫描结束但尚未追平时显示“追平变更”。配置有修订检查，其他窗口修改或自动切换导致冲突时，刷新核对后再保存。

旧代际保留一小时缓冲再清理，只回收其专属向量 collection 与不再需要的密钥，不删除原 BM25 索引或 MySQL 记忆。被取消计划的迟到结果不能切换生效。保留旧代际不代表可以直接回滚到过期数据，回切也通过重建完成。

## 日常状态与诊断

模型表单的“最大并发”默认 4，允许 1～64，保存后生效。同一请求模型名跨空间、地址、版本与索引代际共用一个额度池，索引生成、召回、连接测试与保存前验证都通过同一入口申请；各模型互不占用额度。当前为单进程服务内共享，不提供跨服务副本的分布式限流。

额度不足时公平排队，等待消耗原调用时间预算；取消或结束调用会释放额度。模型已启用、其他配置未变时，仅修改并发直接保存，不发连接测试、不重建向量、不修改密文连接修订；收紧时保留在途计数，等待其自然结束，放宽时唤醒队列。并发不参与向量模型指纹，旧索引与新索引同名时不能各自获得一份限额。

在线召回等待超时使用关键词结果，不触发供应商故障退避；后台等待超时重新排队，不扣供应商失败重试次数。未发送的等待不增加模型用量，HTTP 完成后即释放额度，后续统计与索引发布不占模型额度。只读连接测试遵守已有模型限额，未保存的新模型按默认四并发测试；表单中的未保存值不能临时放宽生效限额。旧 API 客户端省略并发字段时沿用已存值。

- 未配置或停用：保持原关键词检索，不调用模型。记忆、采集、Secret、更正和遗忘继续运行，必要的索引删除继续执行。
- 首次补建：关键词检索可用，完成后自动开启混合检索。
- 模型就绪：关键词与语义候选使用 RRF 融合；保留原空间、修订、遗忘、项目范围、条数与正文预算检查。
- 接口异常：本次回退关键词，短暂抑制连续失败调用；后台向量任务退避重试，接口恢复或修正连接后继续处理。

看板显示当前空间的覆盖状态；系统设置显示全实例进度和失败项；召回调试展示本次语义可用性、模型代际、两路分数、融合排序与耗时。余弦相似度和 RRF 分数仅用于检索排序，不表示准确率。Agent 使用原 recall 工具，无需新增 MCP 配置，实际路径由 retrieval_mode／semantic_available 返回。

设计、并发和测试边界见 [设计说明](实例模型与混合检索设计.md) 与 [开发验证方法](开发运行.md)。真实模型的召回质量需在用户配置资源后另行验证，虚构模型测试只验证协议、排序和生命周期。

## Agent 检索前的能力查询

MCP 新增只读 `get_capabilities`，不带参数，返回当前空间、`capability_version`、`cache_ttl_seconds` 和 `retrieval`。其中 `mode` 为预计的 keyword／hybrid，`semantic_state` 为 disabled／building／empty／ready／updating／degraded，附简短 `reason`、`config_revision` 与 `rebuilding`。只检查配置、当前空间的索引覆盖和已观察到的退避，不调用模型、不探测网络，也不返回地址、Key、其他空间数据或进度统计。

首次检索前读取，可缓存 30 秒；关键词模式提取项目／专名／编号／术语，混合模式可按自然需求查询。首次索引未就绪、空空间或退避期间预计使用关键词；已有生效索引时，新代重建不影响原语义能力，增量未追平显示 updating 并仍尝试混合。

每次 recall 继续返回实际 `retrieval_mode`、`semantic_available`，新增 `semantic_reason` 和 `retrieval_revision`；成功使用语义时 reason 为 null，读取配置之前已失败时修订可能为 null。配置修订变化或降级后刷新能力，必要时改用关键词补查一次。能力快照不保证下一次网络调用成功；读取故障不会伪装成未配置。

写入指引强调共享记忆应脱离当前对话仍可理解，具体组织方式及必要背景由 Agent 按内容判断，不强求固定模板或机器信息；不会为了检索编造事实、答案或同义词堆砌。召回后仍须核对主体与适用范围；有相关背景但缺少所问事实时明确说明未记录，不把相似度当成有答案的证明。正式检索质量与阈值的评估边界见 [检索评测设计](检索评测设计.md)。评测执行代码、样本与机器产物只保留本地，不随仓库提交；仓库保留结论、方法和局限。
