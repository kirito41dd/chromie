# Agent 接入与鉴权

状态：2026-10-28 完成独立接入密钥；2026-10-29 收敛为 Codex 插件与通用接入。本轮实施与验证记录见 [Codex 插件接入实施](Codex插件接入实施.md)。

## 目标与边界

空间密码只交给使用者，用于 Web 登录、接入管理及 Web Secret 查看。每个空间可创建多个 Agent 接入，具有稳定 `agent_id`、可修改的 `agent_name`以及两枚独立密钥。同空间共享记忆；Agent 身份用于授权和来源追踪，不增加用户、租户或第二层数据隔离。

创建时只填写接入名称，不选择客户端。安装方式仅提供 Codex 插件和通用接入，不改变身份、密钥或权限。数据库客户端类型列保留兼容历史；新接入写入 `other`，不作为客户端软件身份或创建契约。

## 凭据与权限

| 凭据 | 允许的操作 |
| --- | --- |
| 空间密码／Web Cookie | 用户登录和接入管理；Web 查看 Secret 继续单独验空间密码 |
| MCP 密钥 | 五个记忆工具与只读安装指南；仅返回 Secret 说明和引用 |
| hook 密钥 | POST 原始消息；不能读取记忆或调用 MCP |
| 开启 Secret 权限的 MCP 密钥 | 另允许本地帮助程序直接调用 Secret HTTP，不改变 MCP 的原文边界 |

Web 登录态拥有当前空间的接入管理权，包括创建／查看／重置密钥及开启 Agent 的 Secret 原文存取权限。Secret 浮层继续单独验空间密码以避免误显；接入管理会话具有授予访问权限的能力。

Secret 存取开关默认关闭。空间密码不再作为 MCP、events 的备选鉴权；两类 Agent 密钥不互通，不接受 Cookie 代替接入密钥。Secret HTTP 保留用户验密通道，并增加明确启用的 Agent 通道。

密钥为密码学随机、不透明 API Key，区分 `cm_mcp_`／`cm_hook_` 前缀。请求通过 `Authorization: Bearer ...` 携带，传输支持 HTTP／HTTPS，TLS 由部署提供；不放入 URL、命令参数、日志、消息正文、普通看板或召回诊断。

**用户明确要求密钥可随时再次查看。**服务端保存 SHA-256 校验摘要及可恢复密文；摘要用于认证，密文仅在已登录 Web 用户主动查看时解密。使用现有 AES-256-GCM／HKDF-SHA256 和持久 P-256 根私钥，按空间、Agent、密钥用途及修订绑定独立上下文，不复用 Secret 载荷的加密用途。根私钥同样必须持久保存并独立备份，不新增重要依赖。

## 生命周期

- 创建时自动生成两枚独立密钥，Secret 权限关闭。
- 名称可修改，`agent_id` 不变；历史记录按 ID 关联当前名称。
- MCP 和 hook 密钥可以分别重置；旧密钥立即停止接受后续请求。
- 停用接入同时禁用两种密钥，重新启用可继续使用未重置的密钥。
- 不删除接入和历史记录，避免来源丢失。列表显示最近成功 MCP 请求及最近成功消息上传时间。
- 当前 rmcp 关闭 legacy_session_mode，沿用无状态 HTTP；每个 HTTP 请求都校验当前密钥，初始化成功不授予后续请求权限；处理实例中的工具调用也绑定当前已认证 Agent。管理修改与业务写入按空间锁顺序完成；重置或停用提交后发起的调用不能沿旧会话继续执行。
- 密钥泄露只授予其已有权限，不能登录 Web 或管理其他密钥；同空间普通记忆仍在该 MCP 接入的权限内。

## 来源与持久化

新增 `agent_connections` 表：空间和稳定 ID、名称、客户端类型、启用状态、Secret 开关、创建／更新时间、最近 MCP／hook 时间。新增 `agent_credentials` 表：空间、Agent、用途、修订、摘要、格式、key_id、nonce、密文和更新时间。

原始事件记录采集 Agent；记忆头记录创建 Agent；每次记忆修订和写回执记录操作 Agent。遗忘也记录操作者。所有关系包含 `space_id`，由应用与数据库共同拒绝跨空间关联。

来源取自已认证密钥，不能由请求正文自报 Agent ID；`client_type` 也由接入配置写入。旧数据保留为空来源，页面显示“历史记录”，不推测或伪造身份。不同 Agent 使用相同事件 ID 或写请求 ID 时不能相互重放回执。离线采集队列固定目标空间和 Agent ID，不能在换接入后误补传。

遵循 schema-first：新增 Rust migration，先在真实 MySQL 执行，再通过 SeaORM CLI 生成 Entity；不手写持久化 Model。

## HTTP 与本机配置

| 地址 | 鉴权与用途 |
| --- | --- |
| GET `/spaces/{slug}/access` | 页面壳；登录后进入接入页 |
| GET／POST `/spaces/{slug}/agents` | Web 登录态，列表／创建 |
| PATCH `/spaces/{slug}/agents/{agent_id}` | Web 登录态，改名、启停和 Secret 权限 |
| POST `/spaces/{slug}/agents/{agent_id}/keys/{kind}/reveal` | Web 登录态，主动查看当前密钥 |
| POST `/spaces/{slug}/agents/{agent_id}/keys/{kind}/rotate` | Web 登录态，重置指定密钥 |
| `/spaces/{slug}/mcp` | 只接受 MCP Bearer 密钥 |
| POST `/spaces/{slug}/events` | 只接受 hook Bearer 密钥 |

用户环境变量可以继续作为简单配置入口：MCP 使用 `CHROMIE_MCP_KEY`，hook 使用 `CHROMIE_HOOK_KEY`，本地 Secret 帮助程序使用开启权限的 `CHROMIE_MCP_KEY`。URL 和空间仍沿用现有变量；`CHROMIE_AGENT_ID` 固定本机采集队列的 Agent 身份。环境不再需要空间密码。支持本机私有 JSON 接入文件，`CHROMIE_CLIENT_CONFIG` 只提供文件路径，方便桌面应用不继承终端环境时使用。文件权限 0600，hook 命令只需程序路径和非敏感配置路径；不将完整凭据写入项目级 hooks。

## Web 交互

“接入”按三个场景组织：

- **连接新 Agent**：独立于列表选择的 CLI 步骤，分别提供安装和初始化命令。Codex 默认不展示手工 MCP 配置；通用接入按需展开 MCP／hook 适配示例。已有接入时指引收起，空列表时展开。
- **接入管理**：默认无选中项。整行点击展开或收起本条详情，展示独立的 MCP 请求和消息上传时间；“等待连接”“有请求记录”“已停用”不混为在线状态。名称编辑支持保存／取消，刷新保留未提交草稿。密钥、权限、重置和私有文件导出在高级区域，收起即清空密钥。
- **CLI 配对确认**：显示公开确认码与实际剩余时间，选择启用的接入或新建，确认按钮放在所选项旁。配对期间隐藏安装指引和高级管理，批准后锁定选择并提示回终端等待；请求结束／网络失败提供对应的恢复入口。返回管理清除 URL 配对参数，改密导致的登录失效与普通参数错误分开处理。

默认不请求或批量下载密钥，不将接入配置保存到浏览器 localStorage。切接入、关闭高级区域、切后台、离页或退出清空明文密钥并使迟到响应失效；回到前台重新读取接入状态。详见 [Codex 接入手册](Codex接入与使用.md) 与 [CLI 统一接入](CLI接入实施.md)。

## 验收

真实 MySQL 验证空库迁移、旧数据升级、生成代码一致性、密钥密文、重启后再次查看；HTTP 验证密码／Cookie／两类密钥／跨空间边界、轮换、停用、Secret 开关；实际 MCP 初始化与五工具闭环验证稳定来源、会话换密钥和旧会话失效；采集验证两类密钥混用拒绝、来源不伪造、离线队列不改投、凭据不进入 stdout／队列。前端检查导航、登录恢复、敏感响应迟到处理和窄屏布局，并在浏览器走查。

本机 `demo` 仅保留虚构接入和测试记忆供使用者查看，不自动修改其他客户端配置或安装 hooks。
