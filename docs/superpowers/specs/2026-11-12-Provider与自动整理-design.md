# Provider 与自动增量整理

本轮把模型连接收敛到实例级 Provider，并让已保存的普通记忆自动形成主题入口。用户只需配置一次服务地址和 API Key，再为语义检索、文本整理分别选择 Provider 与模型。后台按记忆修订推进，人只查看进度和结果。

## Provider 与模型用途

Provider 保存名称、OpenAI 兼容地址和加密 Key；两个用途绑定 Provider ID，保留各自模型名、并发及专业参数。支持多个 Provider，允许同站点使用不同 Key。文本模型高级设置保存输出 Token 预算，默认4096、可调1024～65536；推理模型的思考过程可能占用供应商预算，实际模型测试据此调整，不把该参数归入Provider。实例管理空间管理这些配置，Agent 接入不获得管理权。Provider 不存业务记忆，也不改变空间隔离。

已有两套连接在应用数据迁移时按规范化地址与解密后的 Key 精确匹配合并，不输出 Key、不按网站猜测同一账号。数据迁移在根私钥验证后执行，使用短事务和幂等 Provider 绑定；原向量身份、代际与数据保留。先新增表和可空绑定，旧连接在未迁移时仍可读取；绑定后运行时以 Provider 为准。保留旧 HTTP 配置字段的兼容入口，新页面不再重复收集 Key。

保存 Provider 使用修订校验。修改地址须重新提供 Key 或明确选择无 Key，不把旧凭据自动发送到新地址。连接变化使相关在途文本任务失效，并更新向量连接修订；不因地址或 Key 改变而重建向量。改模型、版本或维度仍沿现有确认与重建机制。模型测试仍按用途调用真实协议，Provider 保存本身不猜测可用模型。

## 自动整理

整理仅处理已有 note，Secret 和原始采集消息不在自动范围。生成的 topic 不再作为下一轮待处理资料，但会作为对照补读。消息提炼继续独立，提炼形成的新 note 后续自然进入整理。

按空间、记忆 ID 和当前修订保存处理进度。首次从较早普通记忆开始，每轮最多 10 条，同项目范围成批；另补读与输入有关或同范围的有限旧主题，避免将主题数算入待处理批次。新增／更正会重新变为待处理，成功且没有产物也推进进度。主题、关系和处理完成标记在同一事务发布，输入改变、遗忘、停用或过期租约均拒绝旧产物。

复用现有持久任务与单项 Worker，不增加独立 Agent 循环。实例设置控制启用、批量、轮次间隔与每日自动调用上限，默认每批 10 条、间隔 60 秒、每日最多 100 次领取处理尝试；没有待处理资料不调用模型。全实例轮询各空间，以最早到期输入推进，避免某空间永久占用队列。临时失败沿既有有限重试；最终失败保留状态并长退避，让其他资料继续。配置修正可重新处理失败项，不重新整理已完成修订。

新保存文本配置默认启用自动整理，可暂停；已有启用的旧配置迁移后先保持暂停，设置页明确说明一次启用后覆盖各空间历史普通记忆，避免升级立即产生未预期模型调用。暂停阻止尚未放行的新调用与在途旧结果发布；共享额度等待结束后在短事务内复核资格并提交放行，已放行请求不能从供应商撤回；人工记忆、主题导航和检索继续可用。

## 页面与验收

系统设置先管理 Provider，再配置两个模型用途；名称、模型、连接状态和保存反馈清晰分层，高级参数折叠。看板移除“整理最近 10 条”日常动作，显示自动整理状态、待处理／完成／失败数量、最近结果与安全错误。用户无需逐批点击。

验收覆盖旧配置迁移与合并、改 Key 同时影响两个用途、改地址保护、管理鉴权、在途连接变化、向量身份保持；自动整理覆盖历史超过一批、无产物推进、修订变化、主题对照、重启恢复、失败不阻塞其他资料、暂停与预算、遗忘不复活。仅在隔离库和虚构空间测试，模型原始产物与执行器不入库。真实模型观察与确定性回归分开报告。本轮不提交、不推送、不访问生产，不新增重要依赖。
