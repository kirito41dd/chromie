# 对话增量提炼与会话标题

用户已同意自动处理采集消息、记录消费进度，并在同次模型调用中生成和更新会话标题。本阶段在现有实例级文本模型、持久任务、共享并发和日用量之上实现，不新增依赖、不自动启用真实空间的原文处理。

## 行为

- 自动整理普通记忆与自动提炼原始对话是两个开关；后者默认关闭。设置明确说明历史及新增原始对话会发往文本模型。两类任务共用批次间隔、每批上限及 UTC 每日尝试额度，交替调度，避免长历史挤占普通记忆整理。
- 会话身份为 `space_id + agent_id（含旧数据的空来源）+ session_id`。内部摘要键采用带长度与来源标记的 SHA-256；会话 ID 不变，标题不是身份。
- 每条消息单独记录 queued/done/failed 与所属任务；没有进度行即待处理。迟到消息、离线补传、处理期间新增消息均能在后续批次被扫描。完成过的事件不因换模型、改标题或重启重跑。
- 每批最多 10 条新消息，等消息收到至少 30 秒后入队；不要求整个会话结束。固定新消息清单，附最多 4 条之前的同会话上下文和有限已有普通记忆用于理解及去重，总输入不超过 128 KiB。过大时减少完整条目，不截断后标记完成。
- 自动产物仅新增带真实消息来源的 note；已存在的结论不重复保存，冲突记录待核对，不覆盖旧 note 或擅自遗忘。允许零产物，仍推进这批消息。Secret 原文不作为普通记忆产物。
- 模型在同一响应给出简短标题。延续当前事项保留原题，明确换事才更新，偶尔插话不改名；不把未确认推测写成标题。记录标题历史；没有自动标题前用首条用户消息摘录。
- 提供手动固定标题和恢复自动命名；固定标题不受模型改写。标题修订与模型快照核对，手动命名不会导致已消费消息再次处理。
- 不做长期滚动摘要副本；有限原始上下文保留真实来源，降低遗忘后派生副本残留风险。遗忘时清空空间内派生标题及历史、取消快照，完成的事件进度保留，未完成批次释放。

## 持久化和事务

新增 `conversation_metadata`（身份摘要键、标题、固定标志、修订）、`conversation_titles`（每次命名的修订、时间、来源）和 `extraction_items`（消息级处理状态、配置修订、任务及冷却时间）。扩展现有组织设置为两个开关与上次任务类型。

模型调用在事务外。管理锁串行化设置与调度，发布持空间锁→管理锁→任务锁，复核设置、输入、标题快照及租约；产物、标题历史、消息完成与任务完成同事务提交。故障保持原进度，暂时故障沿用退避，终态失败同配置冷却 24 小时；换文本配置可提前再试。配置暂停撤销未发送批次，已放行请求仍可能完成网络调用，但不得跨配置发布。

历史来源无需整库回填或改写：反查无完成记录的原始事件即可。新增表由 SeaORM migration 管理，在隔离 MySQL 执行后反生成 Entity。既有记忆、密文、私钥、原始事件保持原值。

## 验收

重点验证增量/零产物/迟到补传/跨 Agent 隔离/失败重试/暂停/遗忘阻断；标题更新、固定与历史；共享预算和两业务公平性。使用独立数据库及虚构资料，模型效果证据放 `.local/`。更新开发 Wiki 与使用说明，完成正式目标检查、Wasm 构建与独立审阅。本阶段不提交或部署生产。

迟到旧批次仍可提炼，但若会话已有更晚发生且已完成的消息，不用旧批次响应覆盖当前标题。单条消息因 JSON 转义后无法容纳时，记录失败并冷却 24 小时，不调用模型，不阻塞其他会话或普通整理；更换文本模型配置可提前重试。
