# 后台记忆维护与主题收敛

用户已批准明确更正自动修订、独立可读性检查、失败诊断及主题收敛。在当前工作区 Inline 分阶段执行，不提交、不部署生产、不引入依赖；保留已有设置页改动和所有数据、根私钥。真实评测资料仅放 `.local/`。

## 行为与边界

- 核对结果区分明确用户更正与推测状态变化。自动修订须有本批新增、逐字匹配的用户更正证据，目标为已完整读取的同范围普通记忆、修订匹配，且证据不早于旧来源；保留旧正文、来源和关系。歧义、多候选同时修改同一目标、来源超限仍待确认。后来的有效修订使旧方案过期，不能顺序覆盖新版本；读取和召回提示当前待确认方案。
- 生成与核对都检查独立可读性：不将省略链接、指代未展开的操作步骤当作完整方法；有来源才补齐，无法补齐暂缓。保持通用正文，不强制机器/项目模板。
- 模型错误细分接口、JSON、结构、输出截断、证据/边界校验；保存阶段、输入字节数及静态错误，不保存模型原始响应。临时故障有限重试；结构问题不原样循环。
- 整理批次提供同范围已有主题，优先复用，不只看最近六个。模型可显式合并已读取的重叠主题；保留全部原有入口，超出关系上限拒绝合并。不擅自跨范围、删除普通记忆或据此合并有歧义的事实。
- 合并后旧主题保存为 `topic_alias` 修订，单条普通引用指向保留主题；不删除旧正文与历史。导航/召回/看板隐藏别名，按旧 ID 读取给出新入口。使用现有修订和关系表，无新增 schema。别名不允许环或指向 Secret，遗忘目标后不再提供入口；迁移包保留类型和引用。
- 模型调用在事务外；发布持空间锁，复核设置、来源、租约和当前修订。保留共享并发、每日预算和暂停行为。

## 阶段与验证

1. 核对/证据类型、独立可读性规则及诊断分类；复用现有事务提取修订应用能力，增加明确更正自动应用与过期方案处理。
2. 读取/召回的待确认提示，Web 区分已自动应用、待确认和已过期，不让过期建议继续显示确认操作。
3. 增大有界主题上下文、复用与显式合并；别名类型、图边界、读取/检索/迁移语义。
4. 用独立 MySQL 和虚构模型响应验证更正时序、并发/遗忘阻断、无效引文、修订幂等、完整性检查、合并不丢关系与跨空间拒绝。更新 Wiki 与使用说明。
5. 正式 bin/lib 及 Wasm 检查、相关测试、独立 Spec/Standards 审阅；备份后更新本地8732并验收。生产不变，不提交。

## 验收重点

旧“随时改时间”→新“只能延期”自动更新；缺少用户明确依据仍保留待确认且读取可知；旧任务不能覆盖后来的修订；方法中 `.../install.sh` 不会当作可执行完整指引保存；相同主题不会每批另建，合并后旧链接可访问、普通记忆与历史仍完整；失败能定位阶段与错误类别，不输出正文。
