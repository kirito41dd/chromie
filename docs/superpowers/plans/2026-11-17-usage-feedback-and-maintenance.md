# 使用结果反馈与独立维护

用户已批准使用结果反馈与独立低频维护；当前工作区 Inline，不提交、不改生产、不引入依赖。保留之前尚未提交的后台维护和设置页实现，基线另存忽略目录。用户云端 Skill 为单独设计范围，本计划不预先实现其存储或执行。

## 交付行为

1. 保留现有“有用”判断，feedback_recall 可独立批量报告确实使用的返回项。使用结果为 succeeded / content_outdated / environment_blocked / unverified；附公开简短原因，服务从原召回取得修订与 Agent 身份，不接受任意未返回对象。未验证可晋级到最终结果；重试幂等，冲突整批回滚，不把所有召回自动视为使用或成功。统计按当前修订分别展示，只表示 Agent 报告，不宣称独立验证。
2. 增加单独开启的低频维护，默认24小时，可调间隔；不依赖新增普通记忆。maintenance_items 按记忆记录有界检查进度、修订、调度时间和快照覆盖边界；内容过时/环境受限的新反馈优先唤起核对，成功记录留给周期检查。无资料不调用模型，暂停不清成功进度，不因低频未使用自动归档。
3. Maintain 与现有两类任务共享模型并发、持久租约及每日尝试预算，轮转调度避免任何一种被饿死。读取同范围普通记忆/主题与有限反馈，调用在事务外，发布前复核设置/修订/遗忘/租约/反馈。主题复用和合并复用现有校验；普通记忆的修改只提出完整草案，标明 Agent 报告依据，经用户确认后追加修订，不能凭反馈直接覆盖事实。
4. Web 分开展示消息提炼与主题维护结果，含更新主题、合并入口、待确认方法修订、原因和处理进度。MCP/配套使用 Skill 明确反馈时机与语义，不采集更多原始工具轨迹，不自动全选成功。

## 状态与持久化

新增 migration 后在独立 MySQL 执行并生成 Entity。recall_items 增加使用结果、原因、报告时间；organization_settings 增加维护开关和间隔；maintenance_items 保存空间＋记忆＋目标修订、状态、任务、到期/完成/请求时间与错误。已有记忆、修订、Secret 和根私钥保全。

一次召回项只表示一次任务观察，最终结果不能被不同结果静默覆盖；新的尝试用新的召回。反馈与“有用”独立，旧修订反馈不计到新修订。反馈快照覆盖到任务入队时点，任务运行期间新到的反馈仍进入下一轮；维护自身更新的主题记录新修订，避免自我触发循环。遗忘清理反馈原因和后台副本，不能通过维护复活内容。
