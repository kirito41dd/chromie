# 后台输出稳定性与记忆质量优化

用户要求排查两阶段处理仍失败的原因，并优化生产观察到的内容质量。当前工作区 Inline 执行；不新增依赖、不改表、不修改生产设置或历史记忆，不自动确认旧修订。保留暂缓的云端 Skill 草案。

## 证据与范围

- 当前16384是单次输出上限，生成／核对分别调用；旧错误只有截断／结构失败分类，不能反推当时各次实际预算和推理消耗。
- 当前system提示词混合五种协议，且包含重复约束。
- 更新主题补回未读分支后未统一检查关系并集容量，可能直到写入才报invalid_argument，无法按模型结构错误缩批。
- 生产已开启维护，前四个完成批次覆盖32项、合并4个主题，无失败；只读观察，不把旧失败归到新版。

## 实施顺序

1. 按类型选择仅本阶段所需提示词，共享安全边界与主题约束。提炼和核对强调独立可读的对象、条件和最新状态；普通答疑或缺主体的一次性评价可空产出／暂缓，不强制项目或机器字段。
2. 草稿引用按对象和关系归一，保留既有未读分支后校验总容量；超限为结构错误。输入说明主题剩余容量，满容量采用明确细分入口，不静默丢引用或放宽32条上限。
3. 模型失败增加阶段、预算、输入／输出／推理Token数及正文长度的安全日志；不记录输入、响应／推理原文或凭据，不增加调用明细表。
4. 同步Wiki。验证关系容量／去重／事务回滚，既有提炼时序、证据、遗忘和维护用例，正式bin/lib Clippy。隔离实例真实模型观察，评测资料留忽略目录。

## 不变量与验收

调用仍在事务外，发布复核空间、修订、配置、来源、租约和遗忘状态。引用去重不能接受未知目标、伪造修订或跨范围引用。超过真实容量须原子失败，不截掉旧入口。日志只含固定枚举和数值。最终按Spec／Standards独立审阅；本轮只改本地，提交和再次生产发布按后续授权执行。
