# Web 交互与视觉优化专项

## 目标与边界

让日常浏览连续、操作有反馈、主要内容容易找到。继续使用 Slint／Rust 和既有浅色紫色风格，不引入依赖，不改变鉴权、Secret 清理、模型任务或数据结构。

当前后端基线为 `5479c5e`。本轮在当前工作区逐步实施；暂缓的云端 Skill 草案不在范围内。

## 第一轮实施

1. **采集消息工作区**：默认直接显示会话；提炼记录另设入口。左右列表与正文各自滚动，选择会话只更新正文，不重置整个页面。窄屏进入正文后可返回原会话位置，翻消息页只重置正文。请求代际继续阻止旧响应覆盖新选择。
2. **信息层级与反馈**：手动提炼和命名收进正文的更多操作；翻页控件留在面板底部，加载／空／失败状态在相关区域展示。修正提炼记录收起后仍占大量空白的问题。
3. **设置导航**：用页内分类区分模型连接、后台处理、用量，减少寻找配置时的长距离滚动。分类切换保留未保存字段和后台请求，不触发整页重载；模型连接与危险维护仍遵守原确认逻辑。
4. **走查与回归**：用真实 Chrome 覆盖会话选择、刷新、翻页、窄屏返回和设置分类；检查键盘操作、正文选择复制、长内容以及结果浮层。将新的交互规则写入开发 Wiki。

## 后续检查方向

看板结果区和最近记忆的密度、接入步骤与配置预览、召回结果与调试信息的主次、迁移预览与解锁反馈、弹窗焦点和关闭后的返回位置。逐页记录可复现问题并验证，避免一次性改完所有页面却没有验收。

## 验收

- 宽屏会话列表滚到中部后切换对话，列表保持位置，正文从顶部显示；不会跳回页面标题或旧提炼记录。
- 正文滚动不会带走会话列表和翻页控件；窄屏返回会话后仍在之前的位置。
- 读取、翻页和失败不会显示成另一会话的正文；切页／退出仍作废在途响应。
- 提炼历史默认仅占实际显示行的高度；更多记录可展开和收起。
- 设置分类切换不丢草稿，不保存配置，不触发模型调用或改变任务开关。
- 通过前端编译、相应状态测试和浏览器走查，再独立审查本轮变更。

## 第一轮结果

以上四步已落地。本地 Chrome 已验证桌面／窄屏会话位置、正文分页、结果切换、键盘选会话、正文复制、设置草稿跨分类保留，以及读取失败后的重试恢复。独立审查发现的“更多操作展开后不可见”和“读取失败误显示为空”均已修复并复核。

Wasm 构建、原生与 Wasm Clippy、39 项前端 Rust 测试和 67 项浏览器桥接测试通过。本轮仅更新本地体验；后续页面仍按上述方向继续走查，不将首轮验收等同于全站优化完成。
