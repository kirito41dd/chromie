# MCP 分工与真实模型日常验证

用户同意精简 MCP 与 Skill 分工，使用测试实例已配置的模型模拟日常使用、发现问题和调整体验；希望整理以后后台自动遍历，先验证效果。本轮在当前工作区 Inline 执行，不提交、不推送、不访问生产，保留既有未提交功能与 Wiki。

## 本轮范围

1. MCP 常驻说明保留跨 Agent 记忆定位、能力发现、来源／授权与 Secret 关键边界。详细检索、组织与接续方法由已有 chromie-memory Skill 的按需参考承接，调用字段仍由工具 Schema／说明负责；无 Skill 的客户端可完成基本使用。
2. 以本机测试库中新建的明确虚构空间，模拟两种 Agent 身份保存、跨会话召回、更正、反馈与仅针对测试记忆的遗忘。用真实已配置文本模型验证主题整理、消息提炼、重复运行与输入变化；不发送现有个人记忆，不读取／输出 API Key。
3. 首轮真实文本任务控制在最多 10 次调用范围，发生同类失败不无界重试；生成内容为测试观察，不能当作模型质量的普遍保证。评测执行器与原始产物放在忽略目录，不进入仓库；不另外调用模型评测 Skill 文案。
4. 有确定证据的实现问题在授权范围内集中修复，按类型／事务边界选择最小回归与编译验证。纯提示词不增加固定措辞测试。同步维护 Wiki 中现状、限制与验证结论。
5. 自动整理的待处理修订、范围／主题选择、空结果处理和成本调度先形成建议；不在缺少预算与调度决定时启用持续模型调用。用质量结果决定下一步机制，不能把当前最新 10 条按钮当作历史增量遍历。

## 保护边界

- 已有实例根私钥只读，不重新生成；模型 Key 由后端解密使用，调用沿用 UA、共享并发和日用量统计。
- 测试空间与资料必须明确标为虚构；不得更正、遗忘或迁移个人既有内容。
- Skill 保持目标与边界，具体组织由 Agent 判断；安全指南仍由 get_setup_guide 提供实时权限。来源 ID 与修订由真实操作产生，不编造关系。
- 原始采集策略不变，任务整理与消息提炼保持独立；暂不新增重要依赖。

## 验证与交付

核对 MCP 初始化指引、工具发现与字段兼容，校验 Skill frontmatter／参考文件与打包。使用真实模型观察主题覆盖、条件保留、派生依据、冲突、重复执行和更正后的主题维护；通过公开 MCP／Web 入口验证日常操作，记录具体输入范围、输出与局限。

修复代码时只运行相关正式 lib/bin 检查和风险对应的产品回归；完成后按需要进行一次独立 Spec／Standards 审查。最后报告提示词改动、真实模型效果、已修问题、尚未实现的自动整理设计与本地可查看的虚构资料。

## 执行记录

- MCP 常驻说明由 1805 字精简为 650 字；已有 Skill 新增按需检索参考，CLI 导出与插件包核对同源文件。没有另行调用模型验证 Skill 遵从率。
- 真实文本模型执行 9 个有限任务，7 个完成、2 个早期失败未归因。主题分组、冲突保留、依据更新、消息提炼、重复提炼与主题扩充的实际观察及限制见 [真实模型验证](../../../wiki/真实模型验证.md)。跨 Agent 召回当次走关键词降级；遗忘另在隔离测试库验证。
- 修复提炼类型校验、安全失败原因、无产物说明、最新结果入口及看板刷新。浏览器检查实际主题与关系阅读，并用临时虚构响应验证任务失败说明和成功清理；已恢复真实响应。
- 独立 Discovery 的唯一阻塞 DAILY-001 为消息提炼页未展示安全任务错误，已集中修正并提交同轮 Closure。正式检查、产品回归与审阅结果以本轮最终证据为准。
- 自动整理仍为下一步设计：按 ID＋修订推进、补读相关主题、空结果推进、预算与退避；本轮没有开启无限持续任务，也没有改变原始采集策略。
