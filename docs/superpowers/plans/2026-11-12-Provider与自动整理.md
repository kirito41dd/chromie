# Provider 与自动整理实施

设计见 [Provider 与自动增量整理](../specs/2026-11-12-Provider与自动整理-design.md)。沿用当前工作区 Inline，不提交；保留前一轮未提交功能。Provider 绑定、任务配置修订与前端状态相互关联，按顺序实施，使用现有依赖。

1. 新增 Provider、自动设置与修订进度迁移，在独立 MySQL 执行后由 SeaORM CLI 生成 Entity。新增可空绑定和默认值；升级重放、旧数据与原根私钥保持。
2. 实现 Provider 管理、受保护的凭据解析／旧配置幂等迁移，两个模型用途改为绑定 Provider。共享配置锁、调用前后连接修订校验；现有模型身份、额度、用量和旧 HTTP 兼容继续保留。测试 Key 轮换、改地址、鉴权、迁移合并和向量代际。
3. 在现有知识任务上增加自动来源与处理修订登记。调度器有限选取普通 note 与旧主题，原子入队、领取时计预算、发布时推进成功进度；失败与暂停按设计退避／取消，保留遗忘边界。验证超过一批历史、0 产物、更正、重启／租约、失败、预算、暂停。
4. 重排 Slint 设置页为 Provider＋用途，首页改自动状态；请求带代次、配置 dirty 状态和安全错误保留。用浏览器验证保存、选择 Provider、旧配置呈现、自动进度和主题阅读，模拟错误单独标注。
5. 同步 Wiki、AGENTS 中已变化约定与使用说明；正式 lib/bin、Wasm 检查和相关产品回归通过后，按同一轮独立 Spec／Standards 审阅收敛。有限真实模型验证只发送新建虚构资料，不启用对现有个人记忆的测试发送。

类型和事务指导沿 type-driven-verification 的领域边界、用例事务与 schema-first 流程。Provider 公共读取不返回密文／Key；跨网络调用在事务外，发布前复核配置、输入、自动设置和租约。处理标记与产物同一提交，不能出现“标记完成但未发布”。固定快照、审阅记录与私有执行器放忽略目录；数据库 schema 与业务数据迁移分开实现。

## 本轮验证进度

Provider Key共享／迁移／轮换与旧向量身份、13条自动历史进度、空结果、跨日额度、重启、更正、主题对照、失败让路及暂停恢复已有隔离回归；原embedding完整生命周期也通过。真实模型的四轮各3批观察依次发现引用类型混用、输出截断等问题；去掉内部调度元数据、明确事件/记忆ID通道并将文本输出预算做成用途参数后，最后一轮3批完成5条虚构记忆。原始记录与执行器只在忽略目录。这不是模型稳定性保证。

独立Discovery的PROV-AUTO-001/002/003已集中修正：用途基线未变才保留草稿同步修订，否则显式冲突与重新载入；等待额度后在发送前重验发送资格；旧入口一次解析真实URL与Key快照。6项产品回归及5项模型设置/草稿测试通过，浏览器已核对两种草稿保留与保存，以及外部用途变化后的冲突恢复；等待同轮Closure复核。本轮不提交、不推送，不更新生产。
