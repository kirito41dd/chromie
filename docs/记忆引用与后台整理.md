# 记忆引用、主题导航与后台整理

Chromie 的记忆面向跨对话、跨设备与跨 Agent 复用。正文组织交给 Agent；结构化引用让服务维护去向、反向引用和派生依据。MySQL 保存权威数据，不另引入图数据库。

本文介绍使用入口和行为边界。表设计、事务、任务状态机及提示词分工集中维护在 [开发 Wiki](../wiki/README.md)，可直接阅读 [记忆与关系](../wiki/记忆与关系.md)、[后台任务](../wiki/后台任务.md) 和 [模型调用](../wiki/模型调用.md)。

## 引用与主题

普通记忆的 `memory_type` 默认为 `note`；`topic` 是简短主题入口，第一行用作显示名称，正文说明用途和去向，细节保留在被引用的记忆中。主题本身也支持来源、修订和遗忘。

`remember` 和 `correct_memory` 的 `links` 每条最多 32 项：

- `reference`：`memory_id` 指向同空间内真实、未遗忘的记忆，省略 `revision`，阅读时跟随当前内容。
- `derived_from`：结论由目标内容整理而来，填写真实读取的当前 `revision`。依据改变时 `get_memory` 的 `knowledge.needs_review` 为 true，提示核对；不会自动将旧依据升级成新事实。

关系随源记忆修订保存。更正时省略 `links` 保留原关系，空数组清空；省略 `memory_type` 保留类型。反向引用只计算当前仍有效的源修订。普通引用允许互链；派生链不能形成循环、不能指向 Secret，单次校验超过 512 个依据节点时拒绝并提示拆分范围。

MCP 的 `get_navigation` 分页返回主题入口，`get_memory_links` 分页返回引用，`incoming=true` 返回反向引用。它们只提供简短入口，具体内容通过 `get_memory` 按需读取；关联与直接检索命中分别表达。支持已知 `project_key` 筛选，返回该项目及空间通用条目。服务继续只按空间做安全隔离。

Web 看板提供主题导航；卡片展开后可进入“阅读与关联”，查看完整公开正文、引用和反向引用，并在关联记忆间返回。Secret 只展示公开元数据，原文仍使用原来的独立验密流程。

遗忘一个依据时，包含其信息的派生记忆同时清理，包含历史派生修订；普通引用不会扩大删除范围。后台快照与冲突说明也可能含有该信息，因此一次遗忘会清理当前空间的整理快照并取消任务，阻断在途写回。

## 可选文本模型

初始管理空间在“系统设置 → 文本模型”配置 OpenAI 兼容 Chat Completions JSON 接口。先配置 Provider 的地址和 API Key，再为文本／embedding 用途分别选择 Provider 与模型；同服务商无需重复配置 Key。Key 加密保存，读取配置只返回是否已保存。切换服务地址时重新提供 Key，或明确选择接口无需 Key，避免把原凭据送到新地址。

连接测试使用虚构探测内容，不读取记忆。保存前也测试连接。模型名称对应全局共享并发，所有业务共同使用配额；请求带 `Chromie/版本` UA。Token 与失败次数复用 UTC 日期＋模型名的累计用量；业务校验拒绝通过任务状态体现。协议要求 JSON object，默认 16384，可在文本模型高级设置调整为 1024～65536 输出 Token、120 秒 HTTP 超时，响应体最多 512 KiB。

首版采用固定后台工作流：选择资料 → 模型输出结构化草稿 → 校验来源、空间、修订、类型及关系 → 事务写回。没有自主工具循环，不启动外部 Agent；ACP 的外部 Agent 接入留作后续适配，不增加当前部署依赖。

未配置或停用时，人工写入、引用、主题导航及现有关键词／语义检索照常工作。停用和改配置会阻止旧任务发布，已有记忆保持可用。

## 整理与提炼任务

- **主题整理**：后台按当前记忆修订分批处理历史、新增与更正，并补读同范围主题；看板展示自动进度。受信任 Web HTTP 仍可指定范围。模型生成带派生依据的简短主题，或更新本次读取过的同范围主题；不能覆盖普通记忆。局部整理保留未读取分支的已有引用。
- **消息提炼**：系统设置独立开启“自动提炼对话并命名”，默认关闭。按空间、Agent 与会话分批处理历史和新消息，已处理事件不重复，迟到补传也能继续；标题随近期主要事项更新。也可在采集消息页主动提炼本页前 10 条消息。所选原始消息会发送到模型，可能包含敏感信息，页面会明确说明；先生成有逐字来源证据的候选，再检索相关普通记忆核对。新结论自动保存，已有普通记忆在角色、来源时序、范围和当前修订校验后自动修订。助手报告保留观察归属，偏好与决定仍须用户原话；证据不足保留现状或暂缓，重复跳过，不再逐条审批。不能凭推测覆盖既有记忆，不能创建 Secret。
- **冲突**：保留指向实际输入的待核对说明，不按更新时间猜测哪条正确，不自动遗忘。首版只针对本次输入检查重复与矛盾，不宣称覆盖整个空间的全部历史。

看板“自动整理”显示后台进度与最近结果，不再提供逐批手动按钮；对话提炼进度也显示在看板；会话页可查看标题历史、固定标题或恢复自动命名；手动提炼仍可在采集消息页独立发起，其产物作为普通记忆后续可进入自动整理。

任务持久化并显示等待、处理、重试、完成或失效。网络故障、限流与服务端故障最多尝试四次，间隔递增；偶发截断或格式错误最多尝试两次，仍失败才缩批或阻断，鉴权问题须先修正配置。工作进程可恢复过期租约，旧执行者不能发布。模型调用不占用数据库事务，提交前重新核对输入修订、来源遗忘状态、配置版本和租约；任一变化都会拒绝旧结果。一次输出全部成功或全部回滚，重试不会重复发布。已知 Codex 标题生成、下一条消息建议等辅助会话保留原始采集用于排障，不参与记忆提炼，浏览中会明确标注。

系统设置可启用自动增量整理，配置每批条数、批次间隔与每日尝试预算；三项自动任务首次默认关闭，勾选后点击“保存任务设置”生效；仅保存或暂停文本模型不会修改已有选择、参数和处理进度。对话提炼有独立开关；只有明确开启，原始对话才进入自动处理。三类业务共用运行参数与每日额度；收到至少 30 秒的新消息可参与下一批，不需要等会话结束。无提炼产物也会完成消息进度。恢复自动命名后，下一批新消息到来时重新判断标题。机制、失败恢复与边界见 [后台任务 Wiki](../wiki/后台任务.md)。

## 迁移与 Skill

新版炼化包使用 v2，携带当前记忆类型和内部关系；导入兼容 v1。源对象 ID 保持稳定，导入新对象从修订 1 开始；派生依据按实际导入修订映射。包不包含所需历史依据、目标内容冲突或关系不同的条目会明确标为冲突，不能悄悄绑到另一份内容。被遗忘的普通引用不导出。

Codex 的 CLI 接入插件同时分发 `chromie-memory` 和 `chromie-setup`，前者指导按需接续、组织引用与 CLI Secret 工作流，后者负责接入诊断。实时权限和工具 Schema 继续由 MCP 提供。更新 CLI 后运行 `chromie hook install` 更新插件，再重载或重启 Codex。

其他支持 Skill 的 Agent 可以导出相同内容后按其规则安装。以下命令在 Bash 与 Nushell 中相同：

```shell
chromie skill export --out ./chromie-memory
```

目标已有不同文件时拒绝覆盖，用户明确确认后才使用 `--replace`。Skill 不携带服务地址、模型 Key 或接入凭据，不修改用户个人 AGENTS.md。

标题仅用于浏览，不是会话 ID 或记忆正文。自动提炼新增有来源的普通记忆；有依据的更正与补充经后端校验自动修订，证据不足保留现状；重复与冲突判断基于有限上下文，不能保证全空间语义去重。

看板和采集消息页的“消息提炼结果”显示最近批次的新增／自动修订／跳过／暂缓数量。展开可选择复制正文、逐字引文和理由；自动修订保留有限历史版本。旧记忆已被更正时，过期方案不能覆盖它。暂缓不要求逐条操作，不会无限重复调用模型。运行预算按阶段计数，一批通常需要生成和核对两次调用；无候选只需一次。


主题收敛会优先复用已有入口，明确重叠的同范围主题可以合并；旧 ID 保留为跳转别名和修订历史，不删除普通记忆。导航、看板及召回展示有效主题，按旧 ID 阅读可跳转。失败按接口、截断、JSON、结构与证据问题分类；结构失败的自动批次逐步缩小，单项仍失败则停止自动重复，详见后台任务 Wiki。

## 实际使用与定期维护

Agent 可通过 feedback_recall.usage 报告真正使用后的成功、内容过时、环境受限或未验证，与“有用”评价独立。结果固定到原召回修订，只接收原 Agent；不会把全部命中自动记为使用或成功。公开原因不含凭据/日志。

在系统设置可单独开启“定期维护记忆”，默认关闭、周期24小时。没有新记忆也逐批核对，优先处理问题报告，沿用共享模型并发与每日预算。主题可自动收敛；普通正文变更经校验后自动追加修订，在看板“记忆维护”查看结果、依据和新旧正文。冷门不自动归档，模型可以判断本批无需变更。完整机制见[后台任务](../wiki/后台任务.md)。

## 历史保留与遗忘

普通记忆与主题默认保留最近 5 版正文，被派生关系依赖的确切版本额外保留；旧版本保留修订号、时间、来源身份和统计所需的小元数据。任务详细结果保留最近 100 条且最长 30 天，较早结果压缩为计数摘要；会话标题保留最近 10 次命名。详情被清理时页面明确提示。原始采集消息和 Secret 不在这轮清理范围内。自动遗忘另行设计，不凭冷门自行删除记忆。首次启用前备份实例配置和数据库，见 [历史保留 Wiki](../wiki/历史保留.md)。
