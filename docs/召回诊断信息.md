# 召回诊断信息

2026-10-28。为独立 Web 召回调试页增加真实检索诊断，当前 checkout 内联实施，不新增依赖、不提交。Secret 仅说明现状与已定流程，本轮不实现其存取。

## 实施边界

- 保留同一套召回选择、空间鉴权、MySQL 当前修订校验和预算逻辑。MCP `recall` 返回结构不变；Web 同源 POST 响应额外包含 `debug`。
- 展示 Qdrant BM25 的候选数量、校验丢弃数量、配置分词器、候选上限、实际响应耗时；客户端调用耗时含索引准备，业务总耗时不含 HTTP 鉴权与响应传输。
- 展示待同步关键词兜底／索引故障后的最近记忆兜底、实际检查数量、命中数量与上限。空白切分的关键词明确标为兜底条件，不冒充 Qdrant 实际 token。
- 只为最终输出的记忆附加命中路径、候选修订和真实 BM25 分数；关键词兜底没有 BM25 分数。分数不代表置信度，不承诺跨查询可比。若读取期间修订变化，不把旧修订分数解释为当前正文分数。
- `max_chars` 继续限制原记忆结果，诊断为额外的有界元数据，最多关联 10 个已输出 ID；不重复正文、不输出被过滤对象 ID、凭据、原始错误、SQL 或连接配置。
- 调试信息继续只在页面内存保留，离开、编辑、清空、退出或旧请求失效时清理；不新增查询日志或历史保存。

## 实施顺序与验证

1. 保留 Qdrant 实际 score、候选修订和服务器耗时，原查询接口保持兼容。
2. 将召回实现移至独立模块，普通调用与 Web 诊断调用共用选择逻辑，记录各路径统计与最终输出关联。
3. 在现有折叠调试区展示概览与逐条命中信息，保留原始 JSON；Qdrant 分词明细仍明确不可得。
4. 验证正常索引、更正后的待同步兜底、索引故障、遗忘、鉴权、预算、前端旧数据兼容与长诊断布局，再完成正式目标检查、构建和服务重启。

真实浏览器验收仍受现有工具访问限制，不改用其他渠道绕过；组件与接口验证不等同于实际浏览器视觉验收。
