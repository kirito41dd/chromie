# 采集消息浏览

2026-10-29，按用户确认的范围在当前工作区顺序实施，不新增依赖，不提交。

## 产品约定

顶栏新增“采集消息”（窄屏显示“消息”）。独立地址 `/spaces/{space}/messages`，沿用空间登录。页面明确标注原始采集消息，与长期记忆区分。

会话以“空间 + Agent + session_id”识别，避免不同 Agent 复用会话 ID 时混在一起。列表按最近收到消息排序，提供 Agent 筛选和分页。点击会话查看用户消息与助手回复，当前页按消息时间排列；默认展示最近一页，可查看更早消息。消息长正文按需展开；调试详情默认收起，显示事件、会话、轮次、项目、消息时间及接收时间。

仅手动刷新；刷新返回最新快照，分页沿用本次读取的时间边界，避免新消息挤动页面。默认每页 20 个会话、30 条消息，服务端限制最大页码。首版不加编辑、删除、导出、全文搜索或自动提取操作。

## 数据与鉴权

- Web Cookie 校验、空间边界、同源检查和 no-store 与既有接入管理一致；接入 MCP／hook 密钥不授予 Web 浏览权限。
- 只读取未遗忘的 source_events，不读取 Secret 表或密文。不把原始正文、查询和鉴权写入 URL、日志或浏览器存储。
- 会话摘要和消息列表只返回有限预览；完整正文只在用户展开指定事件时加载，最大 60,000 字符，超过时明确标注。切会话、筛选、翻页、切页、退出或跨空间立即丢弃旧正文和请求；迟到响应不得恢复旧数据。
- 使用既有 SeaORM Entity 和查询构造，不增加表或迁移，不修改采集链路与持久根私钥。

## 实施与验证

| 入口 | 用途 |
| --- | --- |
| GET `/spaces/{space}/messages` | 无数据的页面壳，登录后加载 |
| POST `/spaces/{space}/messages/sessions` | 按 agent_id（可空）与 page 查询会话；翻页沿用返回的 as_of |
| POST `/spaces/{space}/messages/conversation` | 按 agent_id（空表示历史来源）、session_id、page 与 as_of 查询消息 |
| GET `/spaces/{space}/messages/events/{id}` | 按需读取指定原始事件正文；已遗忘或其他空间的事件返回不存在 |

三个数据接口均使用当前空间 Cookie 和同源校验。列表与正文不会因为看板每 15 秒刷新而自动重新请求。

1. 添加有界会话列表、会话消息与指定事件正文的只读接口。
2. 添加 Slint 会话／消息界面、请求状态与独立导航。
3. 验证跨空间鉴权、相同会话 ID 的不同 Agent 隔离、遗忘、排序、分页、并发新增、长正文，以及请求取消和页面恢复。
4. 构建并启动本机服务，用当前会话的真实采集记录检查宽窄屏，记录实际结果。
